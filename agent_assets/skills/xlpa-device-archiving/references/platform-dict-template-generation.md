# 平台取参 → 生成最新建档模板（经验固化）

> 本文固化「阶段一：从平台实时拉取字典 → 动态生成工程人员 Excel 模板」的完整经验，
> 并说明当前生成器、解析器和参数保存的共同契约。
> 所有池值/码值必须有实测或平台出处，**禁止臆造**；未实测的一律标 `TBD`。
> 当前输出为 `v15-engineer`，字段契约 `fc-v1`：八表（每种监测点类型各自一张明细
> sheet）、字典池、品牌型号级联、独立映射表。历史草案观察不等于当前生成结果或本批现场执行证据。

## 1. 两阶段运行时流程（总纲）

不维护静态模板。每次建档任务前：

1. **阶段一（生成）**：skill 调平台接口拉最新字典，动态生成 Excel
   （下拉全中文名 + 隐藏/可见「映射」表存名称→码值）。
2. **阶段二（建档）**：读表按「映射」表名称→码值翻译后写边缘 `:7500`；
   查不到即报错，不猜。已填表建档使用该工作簿映射，不以最新云端字典替换其含义。

## 2. 平台字典来源（A 类：必须实时拉取）

| # | 参数 | 平台 | 接口 | 历史快照规模（非约束） | 码值字段 |
|---|---|---|---|---|---|
| 1 | 设备类型 | 边缘 :7500 | `getDeviceTypeSelect` | 28 | `code`(=deviceTypeId) |
| 2 | 用户大分类号 | 云端 | `get_device_type_list` | 27 | `deviceTypeCode`(=userBigNo) |
| 3 | 品牌 | 云端 | `get_brand_list` | 160 | `code`(=brand) |
| 4 | 型号 | 云端 | `get_model_list` | 513 | `modelCode`(=decimalNum) |
| 5 | 代理通信方式 | 边缘 :7500 | `getDictItemList{dictTypeCode:"CommunicationMode"}` | 18 | `dictItemCode`(=proxyCommType) |

**边缘接口鉴权**：RSA 登录（`getRSAKey`+`login`）→ token + 五头签名
（appCode=5000/token/tokenEncrypt=md5(token+loginStr+毫秒)/dateTime/userId）。
`getDictItemList` 路径为 `POST :7500/sysConfigServer/dict/get/getDictItemList`（**无 /v1**）。

**云端接口**：经 xl-protocol-agent MCP（`get_device_type_list`/`get_brand_list`/
`get_model_list`），Bearer Token，响应 `code=20000`。脚本侧无免登录直连通道
（业务 Token 仅在运行中 MCP 服务内存），故云端取数走 MCP 或转存快照。

## 3. B 类：不从平台拉（固定 / 用户指定 / 手填）

| 参数 | 处理 | 出处 |
|---|---|---|
| 协议代号 | 固定 2 项：200新联MQTT / 202上海MQTT | 用户指定 |
| 波特率/停止位/校验位/数据位 | 枚举下拉，使用用户填写值；不默认填6/0/0/3 | 字段契约及175参数页 |
| 通信端口号 | 前端实际21项下拉；兼容原数字输入；43/44专用模式仍阻断 | 23前端静态源码，详见[模板说明](excel-template-schema.md#通信端口号下拉前端21项) |
| 抄表间隔 | 下拉，UI 固定 7 项，非平台字典；码值为 `userSmallNo` **位域**（见 §5），非 0 基顺序 | 协议备注6「用户小类号配置对照表」 |

## 4. 当前工作簿结构（v15-engineer，每种监测点类型各自一张明细 sheet）

| Sheet | 内容 |
|---|---|
| 系统连接 | 目标IP/端口/账号/密码（键值） |
| 字典 | 一列一池：设备类型/协议代号/用户大分类号/抄表间隔/代理通信方式/波特率/停止位/校验位/数据位/品牌 + 每品牌一个 `型号·<品牌>` 级联列（命名区域 `XLPA_MODEL_<编号>`） |
| 挂载关系 | 挂载点/监测点/网关类型 3 列；**无监测点类型列**，监测点类型由设备名称所在的 `监测点·X` 明细表决定 |
| 网关·8163 | 设备名称/设备条码/代理通信方式(自由填写) |
| 监测点·XLBA | 20 列：设备名称/设备条码/测量点号/分路号/协议代号/用户大分类号/品牌/型号(级联)/抄表间隔/代理通信方式/通信端口号(21项下拉)/波特率/停止位/校验位/数据位/IP地址/IP端口号/采集器地址/电流变比/电压变比 |
| 监测点·照明 | 与 `监测点·XLBA` 列结构完全一致（20 列，同一 20 列契约） |
| 监测点·配电房 | 与 `监测点·XLBA` 列结构完全一致（20 列，同一 20 列契约） |
| 映射 | 可见；表头 `字段(下拉列)/下拉选项(工程人员所见)/后端字段/实际写入值(码值)/出处`；覆盖全部下拉池+固定+派生 |

**级联下拉**：品牌 DV→`INDIRECT("BRAND")`，仍对应字典J列；型号 DV
按当前行`$G2`在`XLPA_MODEL_MAP`精确查找，再由`INDIRECT`引用有界型号区域。
空品牌或未命中时回退`XLPA_MODEL_EMPTY`，公式与边界详见[模板说明](excel-template-schema.md)。

**监测点·X 下拉接线契约**（`监测点·XLBA` / `监测点·照明` / `监测点·配电房` 列结构一致，各表同此接线）：

四项串口列必须各挂 DV，指向 `字典` 对应池列——
`L 波特率→字典!$F`、`M 停止位→字典!$G`、`N 校验位→字典!$H`、`O 数据位→字典!$I`。
`E 协议代号`、`F 用户大分类号`、`I 抄表间隔`使用内联下拉，
`G 品牌`引用命名区域、`H 型号`使用级联、`J 代理通信方式`仍自由填写。
`K 通信端口号`使用前端实际21项内联下拉，覆盖第2～10001行；不新增代理通信端口列。

历史草案曾缺少J/K/L/M数据验证、四串口完整枚举，并把间隔误写为0基顺序。
当前生成器必须使用 §5 同源枚举、映射及数据验证；不能把历史草案缺口描述为
当前版本能力，也不能修改用户已经填写的Excel来掩盖服务端问题。

## 5. 名称→码值映射来源（映射表）

- 设备类型/用户大分类号/代理通信方式/品牌/型号：见 §2 平台码值字段。
- 波特率6/停止位0/校验位0/数据位3/通信端口号RS485-1=1/抄表间隔1分钟=1：监测点3 实测。
- **抄表间隔 → `userSmallNo` 完整码值（位域，协议备注6「用户小类号配置对照表」）**：
  不抄表=0、1分钟=1、5分钟=2、15分钟=4、60分钟=8、15秒=9（bit3+bit0）、24小时=10（bit3+bit1）。
  草案曾用「0 基顺序推断」是**错误**的（会把 15秒 误推为 0），一律以本位域表为准；1分钟=1 与监测点3 实测一致。
  175参数页间隔保存到 `extInfos.userSmallNo`；不派生或双写 `collCycle`。
  合法的“不抄表”码0必须保留，不能通过真假值判断改成1分钟。
- **四项串口档案码值（协议备注2 枚举，与监测点3 实测 6/0/0/3 一致）**：
  波特率 38400→0、115200→1、1200→2、2400→3、4800→4、7200→5、9600→6、19200→7；
  停止位 1位→0、2位→1；校验位 无→0、偶→2、奇→3；数据位 5位→0、6位→1、7位→2、8位→3。
  停止位/校验位/数据位仍保存档案顶层；波特率仅参与`feeNum`，不写档案顶层或下发`baudRate`；
  9600/1位/无/8位→6/0/0/3 已实测，其余值的端到端确认属现场 G2 门槛。
  175页面普通串口“无校验”使用0；历史协议候选码1不能替换页面已核实编码。
- **XLBA参数页四串口由 `extInfos.feeNum` 解码并保存**：175
  `ParamSetMonitorThreeT` handler确认普通端口采用
  `feeNum=(baud<<5)|(stop<<4)|(check<<2)|data`。6/0/0/3得到195，
  这是计算结果，不是费率计数默认值。旧文档“不适用XLBA”的结论已纠正。
  四项只填部分则报错；端口43/44使用特殊周期编码，当前普通模板拒绝。
  档案与候选下发复用同一编码，但20200002完成契约仍未核实，不能现场发送。
- 派生：已确定时以字符串拼接 `dsTypeId=deviceTypeId+userBigNo`。
  本批XLBA地址使用12位条码原文，保留前导零，不套用其他设备地址分段规则。
- 接线方式 lineType 枚举 0未知/1三相三线/2三相四线/3单相：属性目录 enumVal。
- **已确认**：电流变比=`extInfos.cT`、电压变比=`extInfos.pT`，值为变比数值直接透传（监测点3 实测=100），非枚举码值。
- **IP地址/IP端口号与 authParam（监测点表保留列）**：后端落点已由现场抓包确认——
  档案侧写 `extInfos.authParam` 五段逗号串（10.0.17.23 建档抓包），下发侧
  `itemBody.authParam` 编码为 12 位十六进制（IP 四段各 1 字节 + 端口 16 位大端，
  如 `192.168.23.150:21883` → `c0a81796557b`，2026-10-21 下发抓包）。
  串口端口下档案侧 `extInfos.authParam` 透传电表密码；但下发侧**恒存且恒为**
  12 位十六进制，无 IP+端口来源（串口、IP 型端口两列留空、端口未填）时
  一律取页面占位默认 `EEEEEEEEEEEE`（密码不随下发携带）。代理通信方式
  （proxyCommType）对监测点的落点仍未确认，留空即省略，禁止臆造。
  落点确认仍列为现场 G1 待办。

## 6. 填表前生成最新模板

- 触发：工程人员填表**之前**先执行「生成最新模板」。
- 动作：按 §2 拉全量 A 类字典 → 按 §4 结构生成工作簿 → 按 §5 写映射表。
- **命名**：采用 `generate_device_archive_template` 返回的 `file_name` 与下载信息。
- 返回 `file_id`、快照及版本信息；保持工作簿映射与该次生成快照对应。
  填表后上传走 `upload_device_archive_template`（Base64）取得新 `file_id`；
  服务端本地路径入口共用相同解析与执行实现。

## 7. 解析与执行契约

当前reader按设备名称关联「挂载关系 / 网关·8163 / 各 `监测点·X` 明细表」，
监测点类型由名称命中的明细表决定（允许缺表、跨表同名冲突报错、无明细孤立报错）；
从独立「映射」表取得品牌型号码；型号须在对应品牌内唯一解析，未知或冲突报错。
其余枚举与 `field_contract.py` 同源，空值不补历史默认、合法0不得丢失。

生成模板不等于已建档；解析产生task_id，dry-run产生plan_id。
依次经用户确认完成档案/挂载、参数保存及回读，再进入独立确认的通信阶段。
当前20200002、31800008生产门禁保持阻断，持久报告明确列出未执行项。
