# XLPA 自动建档 Excel 任务模板结构说明（v15 名称驱动）

> 本文件定义面向工程人员的自包含 Excel 工作簿结构，模板版本 `v15-engineer`。
> 工作簿由服务端 `read_device_archive_template` 解析，由 `plan_device_archive`
> 生成 dry-run 计划，Skill 负责编排确认与执行。
> 一个工作簿 = 一次任务 = 一个边缘后端（`目标系统IP + 后端端口`）+ 一套凭据。
> sheet 名与列名一律中文，须与 `mcp_server/archiving/templates/generator.py` 常量逐字一致；
> reader 会校验模板版本与必填 sheet/列，不符即拒绝解析。

## 工作簿总览（八表，每种监测点类型各自一张明细 sheet）

| Sheet 名称 | 用途 | 是否必填 |
| --- | --- | --- |
| `系统连接` | 目标系统IP/后端端口/账号/密码/手机号/验证码（配置项/值/说明）+ 隐藏元数据 | 必填 |
| `字典` | 一列一池（设备类型/协议代号/用户大分类号/抄表间隔/代理通信方式/波特率/停止位/校验位/数据位/品牌+级联型号），含四串口命名区域 | 建议保留 |
| `挂载关系` | 拓扑真值；名称驱动 3 列（挂载点/监测点/网关类型），重复挂载点合并居中；**不含监测点类型列** | 必填 |
| `网关·8163` | 8163 网关设备信息（设备名称/设备条码/代理通信方式）；按**设备名称**关联 | 有网关时填写 |
| `监测点·XLBA` | XLBA 抄表参数 20 列；按**设备名称**关联，去重键=设备名称（全局唯一） | 有 XLBA 监测点时填写 |
| `监测点·照明` | 照明监测点明细，列结构与 XLBA 完全一致（20 列）；类型由所在表决定 | 有照明监测点时填写 |
| `监测点·配电房` | 配电房监测点明细，列结构与 XLBA 完全一致（20 列）；类型由所在表决定 | 有配电房监测点时填写 |
| `映射` | 字段/下拉选项/后端字段/实际写入值/出处 | 建议保留 |

> **v15 关键变更**：每种监测点类型各自占用一张独立 `监测点·X` 明细 sheet，监测点
> 类型由**设备名称所在的表**决定（名称全局唯一）；取消旧的「挂载关系·监测点类型」
> 列。解析时**允许缺表**——上传的工作簿只含全部支持类型中的一部分监测点 sheet
> 即正常解析已存在的表；同名监测点出现在两张表 → 类型冲突报错；挂载关系引用的
> 监测点在任何监测点表都无明细 → 报错，不猜类型。新增监测点类型即新增一张
> `监测点·X` sheet 并升级 `TEMPLATE_VERSION`。

所有 sheet 第一行为表头；空行忽略。`密码` 允许明文存在于输入，但工具返回、
日志、报告与错误摘要一律脱敏。模板元数据（`__template_version`、
`__field_contract_version`、`__snapshot_id`、`__source_time`、`__fetched_at` …）
写入隐藏行，reader 仍可读，工程人员不关注。

## Sheet 1：系统连接（全中文配置项）

采用「配置项 / 值 / 说明」三列结构，逐行一个中文配置项。

| 配置项 | 值示例 | 必填 | 说明 |
| --- | --- | --- | --- |
| `目标系统IP` | `192.168.1.175` | 是 | 边缘建档后端主机 IP |
| `后端端口` | `7500` | 是 | 边缘建档后端端口 |
| `账号` | `admin` | 是 | 边缘后端登录名 |
| `密码` | `********` | 否 | 边缘后端登录密码（输出脱敏） |
| `手机号` | `13800000000` | 否 | 联网验证手机号（可选） |
| `验证码` | `123456` | 否 | 联网验证码（可选） |

reader 把「目标系统IP + 后端端口」组合为 `edge_base_url=http://ip:port`，
`账号`→`login_name`、`密码`→`password`、`手机号`→`phone`、`验证码`→`captcha`。
`__template_version` 等元数据行被隐藏，但仍由 reader 读取做版本/契约校验。

## Sheet 2：挂载关系（只表达拓扑，不存条码）

名称驱动 **3 列**：`挂载点`（网关）/`监测点`/`网关类型`。一个挂载点（网关）可对应
多个监测点；**重复挂载点相邻行合并居中**（A 列挂载点、C 列网关类型按块合并，
B 列逐行写监测点）。合并单元格只存左上角值，reader 按行**向前填充**归属到当前挂载点。

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| `挂载点` | 是 | 网关设备名称（全局唯一），pvpr 即网关注册与幂等匹配键；合并块的首行填写 |
| `监测点` | 否 | 挂在该网关下的监测点名称（全局唯一）；非合并、逐行填写 |
| `网关类型` | 是 | 网关设备类型，如 `8163网关`；合并块的首行填写 |

示例（网关 G 挂两个监测点）：
```
| 挂载点   | 监测点     | 网关类型   |
| G        | 监测点1    | 8163网关   |  ← A2:C2 后 A2:A3、C2:C3 合并
| (合并)   | 监测点2    | (合并)     |
```

**去重 / 幂等**：网关按设备名称匹配，基本字段一致为SKIP，有差异为UPDATE；
网关参数项20100024单独列出差异，SKIP仍须参数保存/回读。
监测点按「设备名称」（全局唯一）去重，命中现有监测点 → **UPDATE（需用户确认后按模板
修改参数）**，未命中 → **CREATE**；允许在已有网关下新建监测点。同一网关下
`分路号 + 测量点号` 唯一、**跨网关可重复**；编号重复 → CONFLICT 阻断。

**拓扑定位**：`挂载点 + 网关类型` 在 `网关·8163` 中查该网关 `设备名称 / 设备条码`；
`监测点` 名称在其所属类型的 `监测点·X`（`监测点·XLBA` / `监测点·照明` /
`监测点·配电房`）中查条码等详情，所在表即决定其监测点类型。挂载关系 sheet 不填任何条码。

**跨父不挪动**：命中已存在监测点但挂载网关与后端父级不一致时，保持现状并告警，
**绝不自动改挂载或删除重建**；需要变更时单独协商授权与迁移方案。

**子网关兼挂载点**：同一设备名称可既作为某网关的子设备（出现在「监测点」列），
又作为其他监测点的挂载点（出现在「挂载点」列）。解析器使用统一名称索引去重，
保留首次建立的父关系，不因后续角色变化而清空。具体规则：
- 设备名称全局唯一，无论出现在挂载点列还是监测点列，只创建一个节点。
- 首次出现时设置的 `parent_key` 被保留；后续出现复用已有节点，不修改父关系。
- 同一设备在不同网关下都作为监测点出现（物理上不可能）时，报告多父冲突错误。
- 合并单元格续行不触发冲突检测。

## Sheet 3：网关·8163

按 `设备名称` 关联到挂载关系中的网关节点（即挂载点的 `挂载点` 名称）。

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| `设备名称` | 是 | 对应挂载关系的 `挂载点`（网关）名称 |
| `设备条码` | 是 | 网关条码，经回填作为通讯地址转换与写后回查用（不参与名称去重） |
| `代理通信方式` | 是 | proxyCommType 友好名或已有码值；缺失/未知时报错 |

> **通讯地址转换规则**：网关通讯地址去掉条码第 1、2、7 位后在中间补 3 个 `0`，
> 结果必须为 12 位。示例：`224356000099` → `435600000099`。

## Sheet 4-6：监测点明细表（监测点·XLBA / 监测点·照明 / 监测点·配电房）

每种监测点类型各自占用一张明细表，**列结构完全一致**（下述 20 列），按 `设备名称`
关联到挂载关系中的监测点节点（即挂载关系的 `监测点` 名称）；设备名称出现在哪张
表即取得该表对应的类型（`监测点·XLBA`→XLBA电表=100019、`监测点·照明`→照明=100023、
`监测点·配电房`→配电房=100024）。中文表头由reader翻译为propertyCode后交给profile；
空白不补历史默认，未知映射阻断。profile复用同一解析结果产出三份数据：

- **档案顶层通信字段**（`baudRate`/`stopDigit`/`checkDigit`/`dataDigit`/
  `protocolNumber`/`proxyCommPort`/`agentNum`/`measuredPointNum`）：由 `getDeviceList`
  读取、UI「参数设置」页渲染；下拉列填友好名，profile 按映射表翻译为码值。
- **extInfos扩展属性**：保存四串口位域feeNum、间隔userSmallNo、品牌型号及cT/pT。
  更新保留未指定字段，不发送历史默认或空白覆盖。
- **下发itemBody**：复用档案码值；rtnCode=0表示下发成功。

| 中文列名 | propertyCode | 必填 | 说明 |
| --- | --- | --- | --- |
| `设备名称` | `deviceName` | 是 | 全局唯一关联键 |
| `设备条码` | `deviceBarcode` | 否 | 保留前导零，作为identifier/deviceAddress |
| `测量点号` | `measurNo` | 否 | 写measuredPointNum，不默认1 |
| `分路号` | `roadNo` | 是 | 写agentNum；同网关内唯一，跨网关可重复 |
| `协议代号` | `protocolNumber` | 否 | 新联MQTT协议→200，上海MQTT协议→202 |
| `用户大分类号` | `userBigNo` | 否 | 按支持映射翻译，未知即报错 |
| `品牌` | `brand` | 否 | 工作簿映射至extInfos.brand |
| `型号` | `model` | 否 | 所属品牌映射至extInfos.decimalNum |
| `抄表间隔` | `interval` | 否 | 统一写userSmallNo；5分钟→2，不抄表→0 |
| `代理通信方式` | `proxyCommType` | 否 | XLBA保存落点未核实，填非空阻断 |
| `通信端口号` | `comPort` | 否 | 前端21项下拉；名称转码后保存到proxyCommPort，不默认1；43/44专用模式仍阻断 |
| `波特率` | `baudRate` | 否 | 9600→6，不补默认 |
| `停止位` | `stopDigit` | 否 | 1位停止位→0，不丢零 |
| `校验位` | `checkDigit` | 否 | 无校验→0，不丢零 |
| `数据位` | `dataDigit` | 否 | 8位→3 |
| `IP地址` | `ipAddress` | 否 | 保存落点未核实，填非空阻断 |
| `IP端口号` | `ipPort` | 否 | 保存落点未核实，填非空阻断 |
| `采集器地址` | `collCommAddr` | 否 | 按填写值保存，空白省略 |
| `电流变比` | `cT` | 否 | 按填写值写extInfos.cT |
| `电压变比` | `pT` | 否 | 按填写值写extInfos.pT |

新生成模板的 C、D 列依次为测量点号、分路号；其余字段保持相对顺序。
reader 按表头名称解析，旧列顺序仍可读取，不按列位置改变业务字段含义。

四项串口全填时计算`feeNum=(baud<<5)|(stop<<4)|(check<<2)|data`，
写入extInfos供参数页解码；只填部分时报错。195仅为6/0/0/3的计算结果，不是默认。

> **四串口下拉**：`波特率`/`停止位`/`校验位`/`数据位` 由 generator 写入 Excel 数据验证
> 下拉与映射（命名区域 `BAUD_RATE`/`STOP_DIGIT`/`CHECK_DIGIT`/`DATA_DIGIT`），
> 填友好名即可，profile 负责翻译为码值。`通信端口号`另设21项下拉，详见下表；
> `代理通信方式`仍为原有填写方式，不新增独立`代理通信端口`列。

> **分路号/测量点号会被挂载重置**：`updateDeviceParent` 挂载会把 `agentNum`/
> `measuredPointNum` 重置为 1，故 `edge_mount_device` 在挂载成功后自动重发电表档案恢复
> 模板传入值（返回体含 `agent_num_fixed`）；建档顺序须为「新建 → 挂载 →（工具内部）挂载后修正」。

> 下发需当前plan_id、独立确认、显式非空集合及全部前置回执。
> 20200002下发的成功判断标准为 rtnCode=0。

## Sheet 5：字典（一列一池 + 四串口命名区域）

`设备类型`/`协议代号`/`用户大分类号`/`抄表间隔`/`代理通信方式`/
`波特率`/`停止位`/`校验位`/`数据位`/`品牌` + 每品牌 `型号·{品牌}` 各一列，
数据互不整行对齐（每列独立池）。品牌与四串口命名区域保持不变；型号使用
`XLPA_MODEL_<编号>` 有界命名区域，只包含对应品牌的实际型号，不引用整列。
字典末尾的三个隐藏辅助列保存品牌到区域名的显式映射及空白回退单元格，
不参与「映射」sheet 的业务码值解析。型号下拉通过 `XLPA_MODEL_MAP` 查找当前行
`$G2` 的品牌，再以 `INDIRECT` 引用对应区域；空品牌、未知品牌、无型号品牌均
回退到 `XLPA_MODEL_EMPTY`。品牌中的 `~`、`*`、`?` 按原文匹配，不作通配符。
修改品牌不会自动清空已填型号；品牌与型号不匹配仍由原有建档校验阻断。

## 扩展：接入新的可建档设备类型

新增类型需补profile与明细sheet，并核验generator/reader现有的类型分支；
不能假定只注册profile即可全链支持。`字典` sheet 的 `设备类型` 列是全量字典（阶段零平台拉取），新类型无需在
字典列追加（已是全量），只需让它"可建档 + 在模板中露出专属 sheet"。

接入步骤（新增设备类型时按此执行，先总结经验再动代码）：

1. **探测/定义 contract**（先安全）
   - 确认该 `deviceTypeId`（边缘 getDeviceTypeSelect）、平台字典码、字段落点；
   - 每个字段标注 `EvidenceStatus`：实测 `VERIFIED` / 协议 `PROTOCOL` /
     未核验 `UNVERIFIED`（未核验不得进入可执行模板与下发）。
2. **注册 sheet 契约**：在 `mcp_server/archiving/field_contract.py`
   `SHEET_SPECS` 列表追加一个 `TypeSheetSpec`
   （参照 `GATEWAY_8163_SHEET_SPEC` / `XLBA_METER_SHEET_SPEC`）：
   - `sheet_name` / `device_type` / `device_type_id` / `is_gateway` /
     `fields`（工程列契约）/ `derived_fields`；
   - 核验generator、reader及回读对该sheet的支持并同步实现。
3. **写 profile**：在 `mcp_server/archiving/profiles/` 新增该类型 profile
   （派生 identifier/通讯地址、字段一致逻辑；下发/召测走通用链路，无类型能力位）。
