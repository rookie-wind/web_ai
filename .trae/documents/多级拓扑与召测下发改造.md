# 自动建档：多级拓扑 + 默认规划召测/下发 改造

## Context（背景与目标）

用户填写的模板 `设备建档模板_20260922153429.xlsx` 出现**多级拓扑**：`AI_test3`
既是网关（在 网关·8163 明细表，条码 224356000300），又被挂在 `AI_test5` 下作为
监测点。当前 `excel_reader._parse_topology`（excel_reader.py:446-450）把「监测点」
列节点一律硬编码为 `XLBA电表`，导致子网关被误当电表、缺 road_no/通讯地址报
CONFLICT。

另用户要求 **召测与档案下发默认都规划**（不改模板 system connection），且**下发需
先询问用户、召测执行结果需展示给用户**。

目标：支持网关可嵌套（多级父子）；plan 默认规划召测与下发；执行层面下发先展示
清单再确认、召测返回结果供展示。

**已确认决策**：
- 多级填表：子网关既出现在父块的「监测点」列，又可作为独立「挂载点」块挂自己的监测点。
- 召测/下发开关：不改模板 → 引擎**默认都规划**，执行阶段仍用 confirm 门禁区分"展示/询问"。
- **下发范围：递归跨层** —— 一个网关节点的下发集合 = 其**整棵子树**下所有电表
  （含子网关/孙网关挂载的电表），而非仅直接子级。

---

## 关键探索结论

- `_parse_topology`（excel_reader.py:396-451）用 `gw_seen`/`mon_seen` 两套集合，
  同一名称既作挂载点又作监测点会 **create 两次**（node_map 重复 node_key）→ 根因。
- 名称回填段（read_archive_template:589-603）按 `parent_key` 是否为空分网关卡/电表
  分支 → 子网关 parent_key 非空，误走 `meter_details`（空）→ identifier 为空。
- `engine.topological_order`（engine.py:105-141）按 parent_key DFS，**天然支持 N 层**；
  road_no 冲突按直接父网关（engine.py:335-362）→ 多级无碍。
- engine 下发批次（engine.py:502-524）`510 行 if node and not (True)` 恒为假、不
  过滤，所有带 parent_key 的 CREATE/SKIP 都进父网关 meter_keys → **子网关会被当电表下发**。
- `edge_tools._build_gateway_item_body`（edge_tools.py:1596-1598）只取直接子节点且
  不区分类型，子网关 `supports_deploy=False` 触发 1626 → **整批下发被阻止**。
- 系统连接 sheet 无 allow_deploy/allow_poll 中文项 → TaskConfig 恒默认 False
  （models.py）→ edge_set_device_param(edge_tools.py:840-841)、edge_call_device_data
  (944-945) 硬拒绝下发/召测。

## 实现步骤

### 1. `mcp_server/archiving/excel_reader.py`（核心：多级拓扑）

**(a) `_parse_topology`（396-451）**
- 开头一次预扫描，得到：
  - `gateway_names: set[str]`：所有曾作为「挂载点」前向填充后出现的名称；
  - `gw_types: dict[str,str]`：挂载点名 → 块 `cur_type`。
- 主循环把 `gw_seen`/`mon_seen` 改为统一 `created: dict[str, TopologyNode]`（key=node_key）：
  - **挂载点 `cur_gw`**：`created` 无 → 新建网关 `(device_type=cur_type or "", parent_key="")`；
    有则仅当 `cur_type` 非空时补填 device_type。
  - **监测点 `mon`**：
    - `mon in gateway_names` → **子网关**：`created` 无 → 新建
      `(device_type=gw_types.get(mon) or 兜底, parent_key=cur_gw)`；已有 → 把 `parent_key`
      设为 `cur_gw`（不重复 create），device_type 空则补。
    - 否则普通电表：`mon in created` 报「监测点名重复」；否则新建 `device_type="XLBA电表"`。
  - 子网关 device_type 优先取 `gateway_8163.Gateway8163Profile.device_type`（单一真源），
    兜底常量 `"8163网关"`。

**(b) 名称回填段（589-603）** 改为**按名称存在性**取明细（不再按 parent_key）：
```
detail = {}
if key in template.gateway_details:
    detail = template.gateway_details[key]
elif key in template.meter_details:
    detail = template.meter_details[key]
node.detail = detail
node.identifier = detail.get("deviceBarcode", "")
node.road_no = detail.get("roadNo", "")
```
用 `key in` 而非 `.get(key) or ...`，避免空 dict 误落电表分支。

### 2. `mcp_server/archiving/engine.py`（默认规划召测/下发 + 下发批次过滤）

- **build_plan（442-449）**：
  - `deploy_allowed = meter_count > 0`（去掉 `bool(task_config.allow_deploy)`；meter>0 才可下发）；
  - `plan.poll_planned = not link_blocked_gateways`（去掉 `bool(allow_poll)`，默认规划召测）；
  - 删除 450-453 两条「未允许下发/召测」warning，改一句「召测/下发默认规划，执行前需用户确认」。
- **下发批次循环（502-524）**：新增一个把「网关 → 子树电表」折叠的函数
  `_collect_subtree_meters(ordered, gateway_key) -> set[str]`：
  - 按 parent_key 从入参 `ordered` 构建 `children: dict[key, list[child_key]]`；
  - 从 `gateway_key` 出发 BFS/DFS，收集整棵子树中**所有 `profile.supports_deploy`
    电表节点**（排除所有网关节点），返回其 node_key 集合；
  - `gw_batches.setdefault(gateway_key, []).extend(_collect_subtree_meters(...))`，
    使父网关下发集合包含子网关/孙网关下的全部电表。
  - 保留 `deployable_meter_keys`（值=deviceId 已回填的 CREATE/SKIP 电表），用于
    itemBody 构造时取到所选电表。
- 同步 docstring 与注释（439-441 行 allow_* 表述）。

### 3. `mcp_server/edge_tools.py`（下发询问 / 召测展示 / 多级下发防破坏）

- **edge_set_device_param**：移除 840-841 `if not cfg.allow_deploy` 硬拒绝（保留 843
  confirm 守卫）。可选增强：confirm=False 时返回**下发预览**（meter_count/meter_keys/
  payload，`preview=True, executed=False`），confirm=True 才真正下发 → 先展示清单再确认。
- **edge_call_device_data**：移除 944-945 `if not allow_poll` 硬拒绝（保留 947 confirm）；
  返回结构化 `target_data/monitor_valid/data_time`（对齐 edge_call_monitor_debug 口径）供展示。
- **`_build_gateway_item_body`（1596-1598）**：`all_meters` 改为递归收集
  `gateway_node_key` 整棵子树下的电表节点（复用 engine 的 `_collect_subtree_meters`
  逻辑：从该网关出发收集所有 `supports_deploy` 电表，排除网关），而非仅直接子级。
  这样父网关下发覆盖子网关下的电表，且不会因 1626 `supports_deploy=False` 被阻断
  （子树中网关已被排除）。**下发/召测对象按"网关 key → 整棵子树电表"一致**。
- `edge_call_clock`（983）已只校验 confirm，不改。

### 4.（可选，建议本轮不做）
`meter_xlba._DECLARED_COLUMNS`（meter_xlba.py:23-33）补 deviceName/interval/model/
proxyCommType 仅消 dry-run 告警，不影响建档；**不属硬需求**，避免用"消告警"掩盖未实现字段。

### 5. 测试 `mcp_server/tests/test_archiving_template.py`

- 新增多级拓扑用例：挂载点=G1/监测点=SG，挂载点=SG/监测点=M1；断言
  `SG.device_type=="8163网关"`、`SG.parent_key=="G1"`、`M1.parent_key=="SG"`、
  `SG.identifier=="<条码>"`、节点数正确、无重复 node_key、无 errors。
- 新增默认规划用例：`allow_deploy=False, allow_poll=False` 时
  `deploy_planned=True`（含电表）且 `poll_planned=True`。
- 新增**递归跨层**用例：G1 → SG(子网关) → M1、M2；断言 `_collect_subtree_meters(G1)`
  同时含 M1、M2，且 G1 的 `deploy_batches.meter_keys` 包含子树全部电表而不含 SG。
- **更新现有 2 个用例语义**：
  - `test_deploy_off_when_not_allowed`（329-336）：改为默认也规划下发；
  - `test_deploy_batches_not_to_blocked_gateway`（697-707）：`deploy_planned is False`
    成因更新为「网关缺 proxyCommType → link_blocked」。
  - 检查/更新其他依赖 `allow_deploy=True` 的夹具（如 700、975 行）。

## 验证方式

1. 复用脚本调用
   `read_archive_template("设备建档模板_20260922153429.xlsx")`，打印每个 node 的
   node_key/parent_key/device_type/identifier、errors/warnings → 确认 `AI_test3`
   仅一个节点、device_type=8163网关、parent=AI_test5、identifier=224356000300。
2. 对同一 template 调 `build_plan(template, {})` → 确认 `deploy_planned/poll_planned=True`，
   `deploy_batches` 不含子网关。
3. 集成：plan → `edge_set_device_param(confirm=False)` 返回下发预览 → `confirm=True`
   真正下发；`edge_call_monitor_debug` 观察 monitor_valid/target_data 展示。
4. `pytest mcp_server/tests -q` 全量回归通过；`-k "topo or deploy or poll"` 定向跑新用例。

## 风险 / 边界
- 多级建档/拓扑/road_no 冲突正确；**下发按"网关 key → 整棵子树电表"递归收集**，
  父网关下发覆盖子网关/孙网关下电表、单一批次下发，itemBody 构造与批次一致。
- 「默认规划下发」会改变 plan 语义，更新受影响的现有测试（见步骤 5）。
- 校验位/型号等字段未消费仅告警不处理（第 4 节不做）。
