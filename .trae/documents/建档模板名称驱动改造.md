# 建档模板"名称驱动"改造计划

## Context（背景与目标）

用户要一份能与"设备建档模板_草案v14.xlsx"对齐的建档模板，并明确了两处与当前 skill 生成版不一致的根因及决定：

1. **挂载关系 sheet 列结构不同** → 改为**名称驱动**（3 列：`挂载点 / 监测点 / 网关类型`，重复挂载点行**合并居中**），不再用"条码 + 父条码"4 列树形。
2. **系统连接 sheet 不同** → 改为**全中文配置项**（`目标系统IP/后端端口/账号/密码/手机号/验证码`，表头`配置项/值/说明`），模板元数据（`__template_version/__snapshot_id/__source_time`…）**隐藏**到隐藏行或隐藏 sheet，不干扰工程人员。
3. 四串口下拉/映射（波特率/停止位/校验位/数据位）互补方向认可：草案缺、skill 生成版已做，须保留在改造后模板中。

当前代码在 `mcp_server/archiving/`：generator 输出 4 列挂载关系 + 英文键系统连接；reader 以条码为主键解析；engine 按条码/条码+分路号去重、SKIP 不 UPDATE。

**目标产物**：生成一份"名称驱动、系统连接全中文、四串口下拉/映射齐全"的 v14 建档模板，且 reader → engine 能正确解析并执行。

---

## 关键架构约定（用户已确认）

### 挂载关系（只表达拓扑，不存条码）
- 3 列：`挂载点`（第1列，网关注）、`监测点`（第2列）、`网关类型`（第3列）。
- 一个挂载点（网关）可对应多个监测点；**重复挂载点行合并居中**（前两列/第三列按块合并）。
- 拓扑定位：`网关名称` + `设备类型(网关类型)` 在 `网关·8163` 设备信息 sheet 中查到该网关的 `设备名称 / 设备条码`；`监测点名称` 唯一，在 `监测点·XLBA` 中查到条码等详情。

### 去重 / 幂等
- 网关：按**设备名称**去重。
- 监测点：按**设备名称**去重（全局唯一）；同一网关下 `分路号 + 测量点号` 必须唯一，**跨网关可重复**。
- 允许：在**已有网关下新建监测点**。
- 若监测点已存在 → **请求用户确认后按 xlsx 修改监测点参数**（从"SKIP 不 UPDATE"改为"确认后 UPDATE 参数"）。

### 系统连接
- 只保留中文配置项（`配置项/值/说明`），字段：目标系统IP / 后端端口 / 账号 / 密码 / 手机号 / 验证码。
- `__template_version`、`__field_contract_version`、`__snapshot_id`、`__source_time`、`__fetched_at` 等元数据**隐藏**（隐藏行或隐藏 sheet），reader 仍能读到。

## 文件改动清单

### 1. 契约中心 `mcp_server/archiving/field_contract.py`
- 更新挂载关系 sheet 列契约：`挂载点/监测点/网关类型`（3 列），去掉 `条码/父条码/设备名称/设备类型`。
- 更新系统连接契约：中文键（`目标系统IP/后端端口/账号/密码/手机号/验证码`）；元数据键标记为隐藏。
- 更新 `_parse_topology` 依赖的 `TOPO_HEADER_MAP` 相关常量（如引用了旧列名需同步）。

### 2. 模板生成器 `mcp_server/archiving/templates/generator.py`
- `_write_topo`：输出 3 列 `挂载点/监测点/网关类型`；对同一挂载点的连续行做**合并居中**（A 与 C 列按块 merge，B 列逐行监测点）。
- `_write_system_connection`：改为中文配置项表头与键；元数据行改为**隐藏行/隐藏 sheet**（设置 `hidden`，仍可由 reader 读取，用现有版式）。
- `_write_meter_xlba`：**保留**四串口 DV 与级联下拉（现状已实现，勿回退）。
- `_write_mapping_sheet`：确认含四串口码值行（波特率0~7/停止位0,1/校验位0,2,3/数据位0~3）。

### 3. 解析器 `mcp_server/archiving/excel_reader.py`
- `_parse_topology`：改为名称驱动——读取 3 列、处理合并单元格获得"挂载点→监测点"归属；挂载点去重、监测点收进对应挂载点；节点主键改 `device_name`，不再用条码。
- 新增/调整：从 `网关·8163`、`监测点·XLBA` 按名称（`设备名称`）回查 `设备条码` 及详情字段，填回 node 的 `identifier`/明细。
- `_parse_connection`：改读中文配置项键（`目标系统IP` 等）→ 映射回 `edge_base_url`/端口/账号/密码/手机号/验证码；元数据从隐藏行读取。

### 4. 数据模型 `mcp_server/archiving/models.py`
- `TopologyNode`：主键/去重相关语义由条码改为名称（`identifier` 由名称回查条码填充）；确认父子聚合字段与草案"一个挂载点多监测点"对应。

### 5. 引擎 `mcp_server/archiving/engine.py`
- `_build_barcode_indexes`：改为按名称建索引；网关=名称，监测点=名称（同一网关下分路号+测量点号唯一、跨网关允许重复）。
- `build_plan`：去重键改用名称；支持"确认后 UPDATE 已有监测点参数"（原 SKIP 分支增加 UPDATE 提示与确认路径），并保留"在已有网关下新建监测点"。
- `topological_order`：改用挂载点→监测点的父子关系（`parent` 为用户确认的挂载点）。跨网关重复的分路号允许、同网关冲突阻断。

### 6. profile 层
- `mcp_server/archiving/profiles/base.py`、`gateway_8163.py`、`meter_xlba.py`：identifier 由名称回查条码；监测点 confirm 后 UPDATE 参数时复用现状字段一致逻辑，不动后端 API 契约。

### 7. 技能与参考文档（发布源 `agent_assets/skills/xlpa-device-archiving/`）
- `references/excel-template-schema.md`：更新挂载关系为名称驱动 3 列（含合并居中说明）、系统连接为中文配置项 + 元数据隐藏、去重键语义。
- `SKILL.md`：阶段零/阶段一说明同步（名称驱动去重、监测点确认后修改参数、已有网关下新建监测点）。

### 8. 测试
- `mcp_server/tests/test_generator_v14.py`、`test_archiving_template.py`：更新期望为 3 列挂载关系、中文系统连接、元数据隐藏、四串口下拉/映射保留。

## 验证方式（e2e）

1. 脚本调用 `generate_template()` 生成新模板，用 openpyxl 断言：
   - 挂载关系 3 列 `挂载点/监测点/网关类型`，且样例含合并单元格；
   - 系统连接表头 `配置项/值/说明`，中文键齐全，元数据位于隐藏行/sheet；
   - 监测点 C/G/J/K/L/M 列 DV 存在，映射含四串口码值行。
2. 用 `read_device_archive_template` 解析该模板 → 断言名称→条码回查、挂载点→监测点归属、无条码主键错误。
3. `plan_device_archive` 生成 dry-run 计划 → 断言网关按名称、监测点按名称去重；同网关分路号重复阻断、跨网关允许；已有监测点给出"确认后修改参数"提示。
4. 跑 `mcp_server/tests` 全量离线回归（不含真实写入）。
5.（可选，待授权）启动 MCP server 后走 skill 阶段零 → 阶段一 → dry-run 全链路验证。
