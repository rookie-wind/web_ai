# 建档字段落点修复：按平台真实惯例（brand/型号/端口存 code）

## Context（背景与目标）

用户实际建档后，在平台页面发现字段问题。经**实探平台**（getDeviceList 回读监测点200 + 平台既有正常 100019 电表），确认真实惯例：

| 字段 | 平台惯例（既有设备） | 我们当前写入 | 问题 |
|---|---|---|---|
| extInfos.brand | `'37'`（**code**） | `安科瑞`（中文） | 应存 code |
| extInfos.decimalNum | `'160'`（**modelCode**） | 空（键错位） | 应存 modelCode |
| proxyCommPort | `1`（**数字码值**） | `RS485-1`（友好名） | 应存码值 1 |
| baudRate/stopDigit/checkDigit/dataDigit | 平台**固有字段**，始终存在 | 已存 code | 无需改 |
| 8163 网关 identifier | — | 缺写 | base_payload 补条码 |

平台行为澄清：波特率等 4 串口在档案是**无条件字段**（回读始终在）；你看到的"选 485 端口才露出波特率"是**平台前端 UI 条件渲染**，不受 server 写入影响。故 **server 无需做端口→波特率条件逻辑**。

目标：按平台惯例与用户澄清，把品牌/型号映射为 code、通信端口号取 xlsx 列值、去掉代理通信方式下拉、补网关卡 identifier、修型号键错位。

用户澄清（关键）：
- **品牌/型号**：只存 code；映射来源 = **模板「映射」sheet 已有（最新）映射**，不是运行时拉平台字典。
- **通信端口号(proxyCommPort)**：**直接取 xlsx「通信端口号」列值**（不转换、不依赖平台字典；用户填什么就写什么）。
- **代理通信方式、通信端口号**：**两列都没有下拉**（自由填写）。
- **端口→波特率**：平台固有字段，server 无条件逻辑。
- **从模板生成开始完善**（generator 是改动起点）。

## 方案

### Step 1 — 网关卡补 `identifier` 条码
`mcp_server/archiving/profiles/gateway_8163.py`（base_payload 约 89-99）
- `if node.identifier: base_payload["identifier"]=str(node.identifier).strip()`（同 meter 272-273）。

### Step 2 — 去掉「代理通信方式」「通信端口号」列的下拉
`mcp_server/archiving/templates/generator.py` `_write_meter_xlba`
- 从 `direct_dropdowns`（338-344）移除 `("代理通信方式", comm_mode_names)` 项（该列改自由填写）。
- 「通信端口号」列本身无下拉（现状即是），确认不动。
- （网关表 `_write_gateway_8163` 的代理通信方式下拉：按"不用下拉"同样移除保持一致。）

### Step 3 — reader 解析模板「映射」sheet 提取品牌/型号码值
`mcp_server/archiving/excel_reader.py` `read_archive_template`
- 新增解析「映射」sheet：读取品牌行（`字段=品牌, 名称, extInfos.brand, code`）→ `brand_name_to_code`；型号行（`字段=型号, "品牌 / 型号", extInfos.decimalNum, modelCode`）→ `model_code_by_brand[品牌][型号]=modelCode`。
- 存入 `template.task_config.brand_name_to_code / model_code_by_brand`（或 template 元数据）。
- **代码源即模板**（映射随模板生成已最新，与用户下拉一致；零网络、零耦合）。

### Step 4 — TaskConfig 挂映射字段
`mcp_server/archiving/models.py`（TaskConfig 63-123）
- 加 `brand_name_to_code: dict`、`model_code_by_brand: dict` 字段 + to_dict/from_dict；默认空 → 现有用例不回归。

### Step 5 — meter profile：品牌/型号翻译 + 键修正 + 端口透传
`mcp_server/archiving/profiles/meter_xlba.py`
- `_DECLARED_COLUMNS`（23-33）加 `model`（消"型号未声明"警告）。
- extInfos 循环（285-295）后置覆写：
  - `brand_code = cfg.brand_name_to_code.get(brand_raw, brand_raw)`（映射来自模板解析）；
  - `model_code = cfg.model_code_by_brand.get(brand_raw,{}).get(model_name, model_name)`（读 `detail["model"]` 修错位）；
  - `ext_infos["brand"]=brand_code`、`ext_infos["decimalNum"]=model_code`。
- `proxyCommPort`（base_payload 255-258）：**保持直接取 xlsx「通信端口号」列值**（`detail.get("proxyCommPort") or detail.get("comPort")`，不转换）。

### Step 6 — 回读校验补 extInfos（指定）
`mcp_server/edge_tools.py` `_readback_verify_device`（1512-1565）比对 brand/decimalNum（期望=code）；proxyCommPort 按 xlsx 值比对。

### 端口→波特率条件
**不实现条件逻辑**（平台固有字段）；仅 field_contract 的 baudRate note 注明平台 UI 条件渲染与 server 无关。

## 验收准则
**平台上实际建档效果符合要求**：建档后回读，`extInfos.brand`=平台 code、`extInfos.decimalNum`=modelCode、`proxyCommPort`=xlsx 通信端口号列值、网关卡 `identifier`=设备条码、代理通信方式/通信端口号两列无下拉。
