# Web 对话接入方案（后端驱动 Agent 运行时）

> 状态：**方案定稿待验证**，已固化为 OpenSpec 变更 `add-web-chat-agent-runtime`
> （proposal / design / 5 份 specs / tasks，`openspec validate --strict` 通过）。
> 本文是面向人的完整方案说明；规格与任务以该变更目录为准。
> 本文所有代码事实均来自本仓库实测，未经核实的推断一律标注为"待验证"。

---

## 1. 结论先行

把现在由 IDE 承担的三件事拆成三层：**交互交给 Web 页面，会话与门禁交给新增的独立后端，
大模型循环与 Skills 执行交给 CLI 运行时**；MCP Server 退回纯工具层，**一行工具行为都不改**。

```
 现状   IDE = 交互 + Host + 运行时   三合一
 目标   Web 交互  |  后端 Host  |  CLI 运行时  |  MCP 工具层   四分离
```

关键的三个取舍：

| 选择 | 放弃 | 换来的 |
|---|---|---|
| 用 Qoder Agent SDK 驱动 CLI | 自建模型循环 + 把 L3 改造成服务端工具 | 同一个"大脑"（SKILL.md）同时服务 IDE 与 Web，无两套实现漂移 |
| 每用户会话 1:1 独立实例与独立凭据 | 一把凭据服务所有人 | 消除身份串号导致的越权写入与归属混淆 |
| 一期禁用命令执行 | L3 的本地脚本执行与打包 | agent 无 shell，同机部署下的远程执行风险被消除 |

---

## 2. 为什么现在不能直接用

当前形态要求使用者有 IDE、会输入 `/xlpa`、能在本机看文件。现场与移动端使用者不具备这些条件，
而对外交付需要一个直接可访问的入口。

同时有两条硬约束不能违反：

- **现有 IDE 接入路径与 `/mcp` 端点必须不变**（这是既有交付资产）。
- **对话状态不能长在 MCP Server 里**。MCP Server 的职责是工具与鉴权；一旦它持有会话、进程池与
  模型编排，"现有功能不变"的承诺就没有保障，且 SDK 与 OCR 的重依赖会污染 `mcp_server` 的环境。

## 4. 目标架构

```
+----------------+   HTTP/SSE   +---------------------+  SDK  +----------------+
| Web 前端       | ------------> | 后端（Host 层）      | ----> | CLI 运行时     |
| 交互 / 决策    | <------------ | 会话·凭据·门禁·池   | <---- | 模型循环·技能  |
+----------------+   事件流      +----------+----------+       +-------+--------+
                                            | HTTP 回环 /mcp (Bearer)  | MCP Client
                                            v                          v
                              +------------------------------------------------+
                              | MCP Server（纯工具层，行为不变）              |
                              | 71 工具 · 鉴权 · plan/confirm · 审计 · 平台/边缘 |
                              +------------------------------------------------+
```

| 层 | 负责 | 明确不负责 |
|---|---|---|
| Web 前端 | 输入与附件、流式展示、计划卡片、决策与补充、PC/移动自适应 | 任何业务判断与凭据存储 |
| 后端（新增，同机独立进程/独立 venv） | 会话生命周期、实例池、身份↔凭据绑定、事件规范化与重放、票据签发与验票、租约与旁观、配额、自有存储与保留期、本地 OCR | 决定走技能还是调工具（那是运行时里模型的事） |
| CLI 运行时 | 大模型循环、加载 SKILL.md、按意图路由、读写会话工作区、作为 MCP Client 调工具 | 持有任何服务端密钥；越出会话工作区；执行命令（一期） |
| MCP Server | 71 个工具、鉴权、`plan_id`/`confirm` 门禁、审计、平台与边缘 API 代理、会话凭据签发 | 不知道网页上有没有人点了确认 |

### 两条不可妥协的实现纪律

1. **后端只通过 HTTP 回环 `/mcp` 调工具**，禁止直调工具函数、禁止使用 SDK 的进程内 MCP。
   因为 `mcp_token_var`、`AuthMiddleware`、`_require_super`、`plan_id`/`confirm`、操作日志全部
   挂在 MCP 请求上下文里，直调等于给公网开一条无鉴权无审计的旁路。
2. **门禁配置必须由后端注入且存放在会话工作区之外**。否则 agent 改写工作区内的配置文件就能
   自行放宽权限，隔离形同虚设。

## 5. 核心流程

### 5.1 一次用户消息

```
[1] 用户输入 "给我一份最新的建档模板"（或附件/照片）
      v
[2] 后端校验会话凭据 -> 复用/签发该会话专属 MCP 接入凭据
      v
[3] 经 SDK 把输入回注该会话的 CLI 实例（每会话一实例）
      v
[4] 运行时加载 SKILL.md -> 按意图路由 -> 决定用技能还是调 MCP 工具
      |      工具调用经 HTTP 回环 /mcp（Bearer=该会话凭据）
      v
[5] 中间输出以事件流回传：text_delta / tool_call / tool_result / artifact / plan_ready / ask_user
      v
[6] Web 分层渲染（卡片优先，重内容折叠）-> 用户决策或补充
      v
[7] 补充 = 下一条用户消息回注；确认 = 服务端签发一次性授权  -> 回到 [4] 循环
```

### 5.2 写入类操作的确认（方案里唯一不可回退的部分）

```
模型 -> 写入工具(plan_id=P, confirm=true)
          |
          v
   PreToolUse Hook（配置注入自工作区之外，agent 不可写）
          |  向后端验票：P 是否有未消费授权
          +-- 无 / 已用 / 过期 / 后端不可达  -> deny   （Fail-Closed）
          +-- 有                            -> allow，授权立即作废

 用户点击卡片上的 [确认执行] -> 后端对该 plan_id 铸一次性授权
```

要点：**"用户已确认"由服务端持有事实，不由模型自述**。现状的 `confirm=true` 是模型自己填的参数，
在公网场景下可能被幻觉或被上传文档的提示注入诱导置真；官方已保证 PreToolUse Hook 的拒绝优先级
高于权限模式，因此这是可用的不可绕过拦截点。

拦截范围只覆盖写入类工具集合（沿用既有 `WRITE_TOOLS` 语义与边缘写动作）。只读/探测不要求授权，
避免每次调用多一次往返、也避免把只读链路绑在后端可用性上。

## 6. 关键设计决策

### D1 会话 : 实例 : 接入凭据 = 1 : 1 : 1

凭据在 CLI 进程启动时随 MCP 配置绑定，运行期不可切换，所以"一个实例服务多人"在技术上就要求
共享凭据。共享凭据的代价是可验证的越权：

```
用户A(只读) login  -> session[凭据]=A/user
用户B(超级) login  -> session[凭据]=B/super   覆盖
用户A 调 add_brand -> 门禁查到的是 B 的 super 角色 -> 以 B 的身份写入平台
                   -> 审计里 owner 也是同一把凭据，无法归责
```

配套结论：旁观者不额外起实例；实例池只允许"用完回收再给下一个人"，不允许并发共享。

### D2 归属主体与接入凭据解耦

凭据一旦带 TTL、可撤销，`owner_id = SHA-256(凭据)` 就会漂移，导致建档任务、模板、阶段报告、
操作日志分区、trace 会话窗、日志回读定位这 6 类状态互相错位。

```
Web 路径： owner_id = SHA-256("webchat:" + 规范化手机号)   稳定，不随凭据变
IDE 路径： owner_id = SHA-256(接入 Token)                  保持现状，不受影响
```

手机号明文只出现在签发请求、准入配置与审计字段中，不作为文件名。

### D3 Token Registry v2 → v3：主键从地址改为凭据

现有结构在同一地址上签发第二把凭据会让前一把立刻失效（多会话会静默互相踢下线）。因此
`entries` 以凭据为主键，地址、接入主体引用、凭据族别（`ide`/`session`）、有效期、撤销状态降为
属性；`is_valid`、撤销、最后访问时间都按凭据判定。迁移沿用既有备份与 schema_version 检测范式，
损坏时"备份 + 建空表 + 绝不授予 system"的保守策略保持不变。

### D4 会话凭据由 mint 端点签发，用独立服务凭据保护

不复用 `MCP_AUTH_TOKEN`：它同时被 `_get_api_token()` 当作系统级凭据使用，且既有规格规定"本机
地址返回管理员 Token"，复用会把"铸票权"和"系统接入权"焊死，无法单独吊销后端。

新增 `WEBCHAT_MINT_SECRET`（高熵、可轮换）+ `WEBCHAT_ALLOWED_IPS`，两者同时满足才签发；签出凭据
一律 user 级、带 TTL 上限与速率限制。Web 准入手机号名单另存独立文件，不写进 `permissions.json`
——后者是云端写权限事实源且会被系统 Token 管理器读写回，不应和"谁能进门"共用变更频率。

### D5 事件契约自定义 v1，SSE + seq + 游标重放

SDK 类型只允许出现在后端单个适配层，业务层与前端只认自有事件（对话增量、工具调用、工具结果、
产物、计划就绪、请求补充、拦截、错误、收尾），统一带 `v`、`seq`、会话标识、时间戳。移动端锁屏
即断连，因此任务必须与浏览器连接解耦，靠 `Last-Event-ID` 续传补齐；未知事件类型前端降级展示。
不引入 WebSocket：单向流已够，且与既有 `/api/*` 鉴权范式一致。

### D6 单写者租约 + 只读旁观

会话有一个执行者租约（默认 45s，前端 15s 心跳），后来者只读旁观并可显式接管（接管先中断当前
执行轮再转移）。否决"每标签页各开会话"：用户以为在看同一个对话而实际内容分叉，且实例数按标签页
膨胀会直接穿透全局实例上限。

### D7 一期禁用命令执行，L3 执行另立变更

禁 Bash 后一期 Web 能做的：取模板、查询、上传、规划、确认写入、回读、报告、下载产物（这些全靠
MCP 工具，不需要 shell）。不能做的：协议转换中"跑测试脚本、打 ZIP"。

代价被明确写成后续工作：需要服务端补 6 个工具 —— `validate_config_format`、`generate_test_data`、
`execute_conversion_test`、`get_test_report`、`save_conversion_config`（**这 5 个已在
`agent_assets/skills/test-validation/SKILL.md:188-193` 规划，并写明"在沙箱中执行"**）+ 打包工具。
因这批工具会改变交付给 IDE 的资源包语义并触发版本升级，独立成后续变更。

否决"极窄命令白名单"：命令是自由文本，变量拼接、相对路径、脚本内再起子进程都无法可靠解析校验。

### D8 隔离：同机部署下只做必要的两层

后端与 MCP Server 同机 ⇒ agent 与服务端密钥处于同一系统用户下，物理隔离不成立。本方案不建低权
账户、不上容器（用户判定：业务数据非敏感），只保留两层：

| 层 | 措施 | 防的是什么 |
|---|---|---|
| 保留 | D7 路径白名单（写只允许会话工作区，读允许工作区 + 资源包只读母本，显式 deny 代码/资源包源/凭据目录）+ 门禁配置放在工作区外 | **改**：污染分发源、改服务代码、改权限事实源（与数据是否公开无关，属供应链与完整性风险） |
| 保留 | D5 一期禁命令执行 | 任意代码执行 |
| 不做 | 专用低权运行账户、敏感文件 ACL Deny | 主要防"看"；按需求方判定接受该保密性残余风险 |

必须记录在案的一点：`permissions.json` 存的是超级账号手机号与验证码，而 `login` 的验证码按
`server.py:1663` 注释"不会过期"；`.token_registry.json` 与 `_uploads` 中的建档 Excel 含明文凭据。
"业务数据公开"不等于这些凭据公开——上述"不做"两项是接受该残余风险的明确决定，不是遗漏。

### D9 产物交付改为后端代理 + 一次性 grant

既有 `/api/archive/templates/<id>?owner=<摘要>` 与 `/api/logs?token=` 把凭据或归属摘要放进地址
查询串（`server.py:2946` 明确"file_id 本身即为票据"）。URL 会被反代日志与浏览器历史留存，与"公网
禁止 URL 传凭据"冲突。新链路统一改为请求头携带会话凭据 + 一次性 grant 的代理下载；同时给这两个
既有端点加公网门控（内网保持既有行为，避免破坏现有客户端）。

### D10 数据落点分道 + 本地 OCR

- 已填建档表格：走服务端既有建档通道（`/api/archive/uploads` → file_id → 快照存储 → 工具读取），
  **不复制进会话工作区**，保持"只有 MCP 碰建档数据"。
- 协议文档与照片：进会话工作区供运行时读取；照片由后端**本地**识别为文本后写入工作区，不引入
  第二个外部数据目的地，运行时因此只需读文本。
- OCR 做成可插拔 provider，默认本地实现；上传入口优先级：文本粘贴 > 电子表格文件 > 屏幕截图 > 拍照。
  识别失败或行列结构无法保留时必须显式提示，不得静默以猜测内容继续。

### D11 会话数据双写，自有存储为事实源

qodercli 的持久会话目录只作为执行加速（省上下文重传、支持恢复），不作为事实源；会话列表与历史
回看以后端自有存储为准。保留期沿用 `cleanup.py` 既有分类语义：

| 数据 | 分类 | 保留 |
|---|---|---|
| 会话工作区临时内容 | `temp` | 会话销毁即清 |
| 产物与模板 | `result` / `template` | 30 天（与 `DEFAULT_TTL_DAYS` 对齐） |
| 含凭据的建档 Excel | `sensitive_temp` | 任务终态后 7 天 |
| 上传的协议文档 / OCR 文本 | `input` | 30 天 |
| 写操作审计日志 | `audit` | 维持现状不清理 |
| 未知分类 | — | 一律保留 |
| 用户主动删除会话 | — | 立即物理删除 |

### D12 工具面按意图收敛

71 个工具全量挂载实测为 35,022 字符（估算 1.6 万~3.2 万 token/轮）。后端按 `xlpa/SKILL.md` 的意图路由表推导会话所需子集，
在会话启动参数中注入。实测：典型建档会话只挂 read+write 两组（18 个工具）共 11,753 字符，**约省 2/3**；
工具名前缀正则只是粗分组，实现时按真实意图重划。

### D13 技能目录只读与作业产物落位（一期前置）

## 8. 成本、配额与并发

| 项 | 默认 | 说明 |
|---|---|---|
| 每用户每日对话轮次 | 100 | 一问一答计一轮；可配置 |
| 全局活跃实例上限 | 4 | 一个实例是常驻 node/bun 进程；超限明确返回繁忙并排队，绝不复用他人实例 |
| 单轮最大工具迭代 | 25 | 防无限循环；超限中止并说明 |
| 同会话订阅数 | 4 | 防一人开多标签页占满连接 |
| 租约 TTL / 心跳 | 45s / 15s | 失联自动释放持有权 |
| mint 速率 | 配置上限 | 超限拒绝并记录 |

配额防的是滥用与成本，并发上限防的是把机器打满，两者不可互相替代。
