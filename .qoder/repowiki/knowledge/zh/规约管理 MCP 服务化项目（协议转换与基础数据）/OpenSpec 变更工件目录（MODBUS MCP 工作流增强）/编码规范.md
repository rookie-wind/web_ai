- 每个变更目录通过 `.openspec.yaml` 声明 `schema: spec-driven` 与 `created` 日期，并在根 `config.yaml` 中统一配置 schema 与可选规则。
- 变更工件按固定四件套组织：`proposal.md` 描述 Why/What Changes/Capabilities/Impact，`design.md` 描述 Decisions/Implementation Plan/Risks/Migration，`tasks.md` 列出可勾选任务，`specs/<capability>/spec.md` 给出能力规格。
- Proposal 中通过 Capabilities 小节区分 New Capabilities 与 Modified Capabilities，并用 Impact 小节显式列出受影响的源码路径。
- Design 中的决策以编号 Decision N 形式逐条记录，每条包含决策内容、拒绝的替代方案及理由。
- Tasks 使用 Markdown 复选框 `[ ]` 标记待办，并按实施阶段分组（MCP 后端、权限保护、Skill 文档、参数查询、平台同步、验证回归），与 design 中的 Implementation Plan 一一对应。
- 最终确认表中的关键参数必须标注来源，来源标记统一为 `MCP:<tool>.<field>`、`references:<file>` 或 `user` 三类。
