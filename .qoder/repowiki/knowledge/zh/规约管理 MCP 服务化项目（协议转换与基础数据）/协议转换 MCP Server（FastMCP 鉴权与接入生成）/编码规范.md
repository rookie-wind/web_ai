- 所有 MCP 工具通过 `@mcp.tool()` 装饰器注册，并在模块顶层以 `TOOL_DEFINITIONS` 列表集中声明名称、类型、状态与描述，保持工具元数据与实现分离。
- 写入类工具统一先调用 `_check_write_permission()` 检查 `access_level_var` 是否为 `system`，否则返回包含 `FORBIDDEN` 码的错误字典后再执行具体逻辑。
- 鉴权信息通过 `contextvars.ContextVar`（`access_level_var`、`source_var`）在 ASGI 中间件层设置、在工具处理器中读取，避免显式参数传递。
- 未实现工具统一返回 `_stub_response(tool_name)`，返回结构固定为 `{status: 'not_implemented', tool, message}`，便于后续替换为真实实现。
- ASGI 响应构造采用统一的 `send({'type': 'http.response.start'...}, {'type': 'http.response.body'...})` 两步模式，并按需设置 `content-type`、`content-length` 等头部。
- 配置项统一通过 `os.getenv` 读取环境变量并提供默认值（如 `MCP_HOST`、`MCP_PORT`、`MCP_AUTH_TOKEN`），使部署无需修改代码即可调整运行参数。
