# web-e2e-acceptance Specification

## Purpose
定义 Web 路径端到端验收的行为契约：建档闭环、协议转换闭环、IDE 回归与
交互要求逐条演示 MUST 能通过真实浏览器路径重复执行并留证，作为
C1~C6 交付能力的整体验收面。

## Requirements

### Requirement: 建档闭环必须可经浏览器端到端完成且未确认零写入

系统 MUST 支持真实账号用户在浏览器中（不依赖 IDE）端到端完成建档闭环：
上传已填表格 → 生成计划 → 确认卡片（含参数摘要）→ 用户确认 → 下发执行
→ 报告回读 → 产物页面下载。全程 MUST 满足：用户未确认不发生任何写入；
每一环节的过程在页面实时可见；产物下载 URL 不携带凭据。

#### Scenario: AC-1 建档闭环演练

- **WHEN** 验收人员以真实账号在浏览器完成建档全流程并在确认卡片确认
- **THEN** 平台数据实际写入成功，报告与产物可在页面下载，
  演练证据（截图/输出）归档 validation 目录

#### Scenario: 未确认分支零写入

- **WHEN** 演练中另起一个会话走到确认卡片但不确认即中止
- **THEN** 平台无任何写入发生，回读确认数据未变化

### Requirement: 协议转换闭环必须可经浏览器端到端完成

系统 MUST 支持在浏览器端到端完成一次真实协议转换：上传协议文档/点表 →
字段映射分析 → 生成转换配置 → 服务端沙箱测试通过 → 配置与打包产物在
页面下载。转换测试 MUST 经服务端 exec 工具真实执行（非模型模拟），
打包 MUST 受测试通过门控。

#### Scenario: AC-2 转换闭环演练

- **WHEN** 验收人员在浏览器提交 MQTT 转换需求并完成测试与打包
- **THEN** 页面可下载 ZIP，解包内容与 manifest SHA256 一致，
  证据归档 validation 目录

### Requirement: 验收全程 IDE 路径行为必须零变化

Web 端到端验收执行的全程中，IDE 侧既有用法（原生 MCP 连接、77 工具
入参/返回、资源包下载）MUST 行为不变，MUST NOT 因 Web 演练产生回归。

#### Scenario: AC-3 IDE 回归

- **WHEN** Web 演练进行中，同期在 IDE 执行既有建档与转换用例
- **THEN** 结果与验收前基线一致，回归记录归档

### Requirement: 交互要求与并发限流表现必须逐条演示留证

验收 MUST 覆盖需求文档交互要求 1~5 的逐条可演示（AC-4），并 MUST
完成并发场景验证：多用户并发与同用户多任务在配额拒绝、限流与降级
时的表现有明确记录（含免费档位账号并发 > 1 的限流现象）。

#### Scenario: AC-4 逐条演示

- **WHEN** 验收人员按交互要求清单逐条操作演示
- **THEN** 每条均有通过/未通过结论与对应证据

#### Scenario: 并发限流记录

- **WHEN** 压测触发会话配额与上游限流
- **THEN** 页面呈现明确错误语义（非静默失败），现象与可承受并发数
  记录归档
