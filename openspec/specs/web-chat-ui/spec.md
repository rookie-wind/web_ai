# web-chat-ui Specification

## Purpose
定义 webchat 浏览器前端单页应用的行为契约：登录准入、会话管理、消息
收发与事件流实时渲染、写入确认交互（含参数摘要）、ask_user 补充输入、
产物上传与下载入口。前端是既有 webchat API 的纯消费方，不新增后端
行为；凭据 MUST NOT 进入 URL。

## Requirements

### Requirement: 前端必须提供登录页并以会话凭据访问全部 API

webchat MUST 在自身端口提供一个不需要预置凭据即可打开的单页入口；未登录
时 MUST 仅呈现登录表单。登录 MUST 调用既有账号鉴权接口，成功后前端仅
持有返回的会话凭据（内存保存），此后全部 API 调用 MUST 以请求头携带该
凭据。登录失败 MUST 显示脱敏错误，MUST NOT 回显明文口令。

#### Scenario: 未登录访问

- **WHEN** 用户直接打开 webchat 地址且未登录
- **THEN** 页面只显示登录表单，不请求任何会话数据

#### Scenario: 登录成功跳转会话列表

- **WHEN** 用户输入正确账号密码登录
- **THEN** 页面进入会话列表，后续 API 请求头均携带会话凭据

### Requirement: 前端必须支持多会话管理与并行任务

前端 MUST 支持创建、列出、关闭与删除会话，同一用户 MUST 可并行持有
多个任务会话（受后端配额约束）。会话列表 MUST 区分活跃与已关闭状态；
创建会话被后端配额拒绝时 MUST 向用户展示明确原因。发送消息与确认类
操作 MUST 满足写租约前置（后端既有约束）：前端进入会话 MUST 先获取
写租约并在租约丢失时自动重取，MUST NOT 把租约类错误（403/409）
当作业务失败展示给用户；只读旁观可不持租约。

#### Scenario: 同用户多任务

- **WHEN** 用户在一个会话执行建档的同时新建另一个会话发起查询
- **THEN** 两个会话独立可用，互不干扰消息与事件流

#### Scenario: 租约丢失后自动恢复

- **WHEN** 用户发送消息时写租约已过期易手
- **THEN** 前端重新获取租约后重发，用户视角消息发送成功，无租约错误文案

### Requirement: 消息流必须实时渲染完整事件并支持断线回看

前端 MUST 经事件流通道实时渲染会话事件（文本增量、工具调用与结果、
产物、门禁拦截、ask_user），刷新或断线后 MUST 凭事件游标重放回看完整
过程。工具调用展示 MUST 可读（工具名与参数摘要），MUST NOT 展示任何
原始凭据。渲染 MUST 分层：进行中回合实时滚动，历史回合可折叠回看。

契约内未定义具体语义的未知类型事件（type=unknown）MUST 被安全忽略或
降级展示，MUST NOT 中断渲染流。本轮结束（收到 turn_done）时若本轮没有
任何可见文本，前端 MUST 回落展示本轮最终结果，MUST NOT 产生空白气泡。
作为“本轮结束”判据的轮次标识 MUST 取事件中的轮次序号字段，MUST NOT
以事件序号推算。

#### Scenario: 断线重连不丢事件

- **WHEN** 事件流连接中断后前端以最后游标重连
- **THEN** 中断期间产生的事件被补收，画面与完整过程一致

#### Scenario: 刷新后回看

- **WHEN** 用户刷新浏览器并重新进入同一会话
- **THEN** 页面回放该会话全部已持久化事件，包括此前的确认与拦截记录

#### Scenario: 未知事件不破坏渲染

- **WHEN** 事件流中出现前端未预期类型的事件
- **THEN** 页面仍正常渲染后续事件，无脚本异常中断，无凭据或原始结构直接展示

#### Scenario: 本轮无文本时不出现空白气泡

- **WHEN** 某轮结束但未产出任何文本增量事件
- **THEN** 页面展示本轮最终结果或明确的状态提示，不留下无内容的空气泡

### Requirement: 写入确认卡片必须呈现参数摘要且未确认零写入

前端收到 `gate_blocked` 事件时 MUST 按"是否需用户补充参数"分流，而非一律弹卡：

- 当被拦工具在参数登记表（`GATED_PARAM_REGISTRY`）中登记了需用户直接提供、
  且模型常缺失的入参（如 `edge_get_token` 的边缘凭据）时，前端 MUST 弹出
  **参数表单卡**并暂停本轮进度，卡片按登记项渲染输入：敏感项以掩码输入、
  必填项标注、已由模型提供的必填项预填（敏感项不预填），使用户提交对象与
  模型将提交对象一致。
- 对**仅需确认、无需补参**的写入，前端 MUST NOT 弹出会暂停进度的模态确认卡；
  其确认 MUST 由**会话内**承载：门禁拒绝回传模型后，模型 MUST 在会话流播报
  将执行的操作名与**关键参数摘要**（品牌/型号/计划标识/影响台数等；一键建档类
  由后端按计划域数据反查，反查不足时明示"摘要不可用，仅显示计划标识"），并
  请求用户回复口令 `/确认`；收到口令即铸票并续跑。
- 绝对禁止类与护栏自纠错类拦截（`confirmable` 为 false，如业务登录、内置读
  越界）确认亦无法解除，MUST NOT 弹出会暂停进度的确认卡，MUST 降级为一行
  弱提示（不打断转圈、不进待确认队列）。

无论经卡片提交还是会话口令，用户确认前，系统 MUST 不发生任何平台写入
（后端门禁保证，前端不得预铸造票据）。确认动作 MUST 调用既有 confirm 端点
铸票，并 MUST 在事件流中可见确认结果；用户拒绝或不操作时写入 MUST NOT 发生。
当确认成功但本轮仍在执行（`turn_running`）时，前端 MUST NOT 丢弃续跑，而 MUST
把"带参续跑/发起新一轮"登记为待办，在本轮结束（`turn_done`）时自动补发。

确认所用端点 MUST 遵守后端写租约前置：当前连接未持有写租约时，前端 MUST
先获取租约再发起确认，MUST NOT 把租约冲突（409）当作业务失败提示用户；
租约过期时 MUST 能重新获取并重发确认。

#### Scenario: 确认卡片含参数摘要

- **WHEN** agent 请求一项需补参的写入（如 `edge_get_token`）而被门禁拦下
- **THEN** 参数表单卡展示操作名与关键参数摘要（模型已提供的非敏感项预填、
  敏感项掩码留空），用户确认前写入不执行；仅需确认的无参写入其等价摘要
  改在会话流播报后再请用户回复 `/确认`，确认对象与将提交对象始终一致

#### Scenario: 参数表单卡收集凭据

- **WHEN** agent 调用登记了入参的工具（如 `edge_get_token`）被门禁拦下
- **THEN** 弹出参数表单卡、暂停本轮进度，用户填写凭据并提交后写入才执行，
  事件流出现确认通过记录

#### Scenario: 无参写入经会话口令确认

- **WHEN** agent 请求一项无需补参的写入而被拦
- **THEN** 不弹出暂停进度的模态卡；模型在会话流播报操作与参数摘要并请求
  回复 `/确认`，用户回复后铸票、写入执行

#### Scenario: 未确认零写入

- **WHEN** 写入门禁拦下后用户既不提交表单也不回复 `/确认`
- **THEN** 对应写入未发生，后续同目标写入请求仍被门禁拦截

#### Scenario: 确认落在执行中轮次时续跑不丢失

- **WHEN** 用户在轮次仍在执行（`turn_running`）时完成确认
- **THEN** 续跑被登记为待办并在本轮 `turn_done` 自动补发，不出现"点了没反应、
  任务停住"

#### Scenario: 租约缺失时先取租约

- **WHEN** 用户确认而当前连接已不再持有写租约
- **THEN** 前端先重新获取租约再发起确认，最终确认成功，不向用户展示租约类
  错误文案

#### Scenario: 绝对禁止类拦截降级为弱提示不暂停进度

- **WHEN** 前端收到 `confirmable` 为 false 的 gate_blocked 事件（如业务登录、
  内置读越界）
- **THEN** 不弹出会暂停进度的确认卡，改呈现一行弱提示，本轮转圈与执行
  不被打断，事件流仍保留该拒绝记录

### Requirement: ask_user 交互环必须可在页面完成补充输入

前端 MUST 支持两种提问来源并在会话界面呈现提问内容与补充输入入口：
事件型（事件流出现 ask_user 事件）与本轮结束型（本轮以模型提问文本
结束且未发起工具调用）。用户提交补充后 MUST 以普通消息进入同一会话
使流程继续并保持已有上下文。提问
内容 MUST 保留在历史回看中可见。

#### Scenario: 补充信息后续跑

- **WHEN** agent 因缺少必填字段发起 ask_user，用户在输入框补充后提交
- **THEN** 会话继续执行且不再重复同一提问

#### Scenario: 本轮以提问结束时同样可补充

- **WHEN** agent 未产生 ask_user 事件，而是本轮以一句待补充的提问结束
- **THEN** 页面仍呈现补充输入入口，用户补充后下一轮沿用同一会话上下文

### Requirement: 产物必须可在页面上传与下载且凭据不进 URL

前端 MUST 经一体化 composer 的［＋］控件选择文件并**先暂存为 chip（不立即上传、
不解析）**，发送消息时 MUST 才上传暂存文件并将其引用随消息发送。上传通道 MUST 按
文件扩展名自动匹配（xlsx/xls/xlsm→建档表格、图片→截图（OCR）、其余→文档），默认
通道 MUST 为文档，MUST NOT 提供手动通道下拉。上传期间前端 MUST 禁用［＋］加文件
控件并显示忙碌提示，MUST NOT 重复提交同一文件；上传结束后 MUST 恢复控件，失败时
MUST 提示错误，暂存 chip 保留以便重试或移除。事件流出现 `upload_text` 事件时 MUST
展示文本提取结果或显式告警。事件流出现 artifact 事件时，前端 MUST 提供该产物的下载
入口；下载 MUST 经请求头或一次性票据由后端代理取回，URL MUST NOT 携带会话凭据或
一次性票据原文。

#### Scenario: 上传驱动建档

- **WHEN** 用户上传已填建档表格并要求执行
- **THEN** 文件进入会话工作区，流程使用其内容

#### Scenario: PDF 自动走文档通道

- **WHEN** 用户选择 PDF 文件
- **THEN** 上传通道自动切换为「文档」，不会误走建档表格通道

#### Scenario: 上传期间防重复

- **WHEN** 上传请求尚未返回
- **THEN** ［＋］加文件控件禁用并显示“上传中…”，再次点击不产生重复请求

#### Scenario: 后台文本提取结果可见

- **WHEN** 事件流出现 `upload_text`
- **THEN** 页面显示已提取的文本路径与字数，或显示提取失败告警

#### Scenario: 产物下载不暴露凭据

- **WHEN** 用户点击产物下载
- **THEN** 下载成功，浏览器地址与历史记录中不出现凭据

### Requirement: 前端必须可在移动浏览器正常使用

页面 MUST 采用响应式布局，主流移动浏览器 MUST 可完成登录、对话、确认与下载全流程；
确认卡片在移动端 MUST 完整展示参数摘要且按钮可触达。移动端表单控件（composer 文本
输入、模型选择、确认卡输入）MUST 使用不小于 16px 的字号，避免 iOS Safari 聚焦时
自动放大页面；MUST NOT 以 `maximum-scale=1` 禁用用户缩放。模型选择控件 MUST 有
占位 option，未开会话时 MUST NOT 仅余空箭头。登录后主视图 MUST 无需手动缩放、
捏合或滚动即可触达全部入口（顶栏会话入口、composer、发送）。

#### Scenario: 手机完成确认闭环

- **WHEN** 用户在手机浏览器收到写入确认卡片
- **THEN** 可阅读完整摘要并完成确认或拒绝

#### Scenario: 聚焦不放大页面

- **WHEN** 用户在 iPhone 聚焦 composer 文本输入或模型选择
- **THEN** 页面不被自动放大，顶栏保持可见，无需手动捏合缩小

#### Scenario: 登录后页面完整

- **WHEN** 用户在 iPhone 完成登录进入主视图
- **THEN** 页面呈现完整主视图，无"页面不全、需手动捏合缩小"的现象

### Requirement: 执行中必须提供停止入口

前端 MUST 将发送与停止合一为切换按钮：空闲态为「发送」；轮次执行期间 MUST 变为
停止态（转圈/停止图标），点击后 MUST 经二次确认再调用 `POST /api/sessions/{id}/abort`。
`turn_done`、`turn_aborted` 或 `session_closed` 事件到达后 MUST 恢复发送态；页面
重新载入时 MUST 依据会话列表的 `turn_running` 恢复按钮状态。中止后 MUST 展示
“已完成的写入不会回滚”。

#### Scenario: 停止按钮可见

- **WHEN** 消息发送成功且轮次正在执行
- **THEN** 发送按钮变为停止态（转圈/停止图标），直到本轮结束或中止

#### Scenario: 重载后恢复

- **WHEN** 用户刷新页面且服务端仍有执行中的轮次
- **THEN** 按钮按 `turn_running` 恢复为停止态

#### Scenario: 中止后的提示

- **WHEN** 收到 `turn_aborted`
- **THEN** 页面显示“任务已中止；已完成的写入不会回滚”，按钮恢复发送态并允许继续输入

### Requirement: 输入区必须提示可选路由前缀且不得强制

前端输入区 MUST 以提示文案说明可选路由前缀：`/web` 强制网页检索、`/xlpa`
强制协议助手，并说明不带前缀时自动判断。提示 MUST 允许紧凑形态：输入框
失焦时占位提示 MAY 为单行短文案（含 `/web`/`/xlpa` 关键字与可选语义），
但输入框获得焦点时占位提示 MUST 展开为含各前缀完整释义与“不带前缀自动
判断”的完整说明。提示 MUST NOT 要求用户每次输入都携带前缀；前端 MUST NOT
把 `/` 当作必须的命令入口，MUST NOT 拦截或改写用户输入，MUST NOT 新增会
改变会话模式的开关。前缀的识别与剥离由 Agent 侧完成。移动端表单控件
≥16px 字号契约不受紧凑化影响。

#### Scenario: 用户直接输入不带前缀

- **WHEN** 用户在输入框输入普通任务且不带 `/web` 或 `/xlpa`
- **THEN** 消息按原样发送，由 Agent 自动判定路由

#### Scenario: 用户使用可选前缀

- **WHEN** 用户在输入框以 `/web` 或 `/xlpa` 开头输入任务
- **THEN** 前端原样发送该文本，不做拦截或改写；Agent 识别前缀并强制本次路由

#### Scenario: 输入提示不构成强制

- **WHEN** 用户查看输入区提示
- **THEN** 提示只说明前缀为可选项，不出现“必须使用前缀”的要求

#### Scenario: 失焦紧凑聚焦完整

- **WHEN** 用户未聚焦输入框时查看输入区
- **THEN** 占位提示为单行短文案；聚焦输入框后占位提示展开为含前缀完整释义
  与“不带前缀自动判断”的完整说明，失焦后恢复紧凑形态

#### Scenario: 紧凑化不破坏反缩放契约

- **WHEN** 用户在移动端聚焦输入框或模型选择
- **THEN** 表单控件字号仍不小于 16px，页面不被自动放大

### Requirement: 新建会话必须提供账号选择对话框

前端新建会话 MUST 提供对话框供用户选择 Qoder 云账号：默认账号 或 自带 PAT；
自带 PAT 输入 MUST 掩码，MUST 提供"记住"勾选且默认不勾。提交后创建为异步过程：
对话框 MUST 立即关闭并进入新会话，主视图 MUST 显示"正在初始化"状态并禁用发送与
附件入口；初始化完成（就绪事件到达）后 MUST 解锁输入并加载模型清单。初始化失败
MUST 向用户展示后端给出的可辨识原因，失败会话 MUST 在列表中呈失败态且可删除；
当失败源于自带 PAT 时，前端 MUST 重新打开创建对话框、回填失败原因与已输入的
账号来源/PAT/记住勾选（MUST NOT 回显 PAT 明文，MUST NOT 丢失用户已输入内容），
用户可修改后直接重试。"记住 PAT"MUST 仅在该次创建的就绪结果确认后持久化，失败
MUST NOT 写入。凭据 MUST NOT 进入 URL。默认账号不可用时 MUST 提示需自带 PAT。

#### Scenario: 选默认账号建会话

- **WHEN** 用户在新建会话对话框选择默认账号并提交
- **THEN** 对话框立即关闭并进入新会话，输入区显示初始化状态，就绪后可正常对话

#### Scenario: 自带 PAT 掩码输入

- **WHEN** 用户选择自带账号并输入 PAT
- **THEN** 输入以掩码显示，提交后 URL 与界面不出现 PAT 明文

#### Scenario: 校验失败提示

- **WHEN** 用户提交自带 PAT 且初始化失败（如 PAT 无效或过期）
- **THEN** 创建对话框自动重新打开并展示可辨识原因，账号来源、已输入 PAT（掩码）
  与记住勾选被回填，用户修改后可直接再次提交

#### Scenario: 初始化中状态反馈

- **WHEN** 会话已创建但初始化（平台授权激活、模型清单加载）尚未完成
- **THEN** 输入区显示"正在初始化（连接平台/加载模型）…"并禁用发送、附件与模型
  切换；会话列表中该会话呈初始化中状态

#### Scenario: 创建失败会话呈失败态

- **WHEN** 初始化失败且非自带 PAT 场景（如平台不可达）
- **THEN** 会话流出现失败原因说明，会话列表中该会话呈失败态且仅可删除

#### Scenario: 记住勾选

- **WHEN** 用户勾选记住并提交有效自带 PAT
- **THEN** 会话就绪后后端持久化该 PAT，下次新建会话预填

#### Scenario: 记住勾选不因失败落盘

- **WHEN** 用户勾选记住但本次创建以失败告终
- **THEN** 该 PAT MUST NOT 被持久化，账号库不新增记录

### Requirement: 输入区必须提供模型选择下拉

前端输入区 MUST 提供模型选择下拉，选项取自当前会话账号的启用模型清单，MUST
展示展示名与成本标记；成本标记 MUST 以 `price_factor` 呈现（形如 `×N`），仅当
模型缺失 `price_factor` 时才以 `is_free` 呈现「免费」，MUST NOT 在 `price_factor`
存在时因 `is_free=true` 而显示「免费」。切换 MUST 对下一条消息生效（消息级），
MUST NOT 改变路由模式或会话模式。下拉 MUST 反映当前预选模型；账号为会话级，
MUST NOT 在会话内提供切换账号入口。

#### Scenario: 下拉呈现账号清单

- **WHEN** 会话初始化完成（`session_ready` 后模型清单加载）
- **THEN** 输入区下拉列出该账号启用模型并含 `×N` 形式成本标记，预选默认模型

#### Scenario: 矛盾口径统一

- **WHEN** 某模型同时下发 `is_free=true` 与 `price_factor=0.1`
- **THEN** 下拉该模型显示 `×0.1`，MUST NOT 显示「免费」

#### Scenario: 消息级切换模型

- **WHEN** 用户改选模型并发送消息
- **THEN** 下一条消息使用新模型，无需新建会话

#### Scenario: 切换模型不改路由模式

- **WHEN** 用户切换模型
- **THEN** `/web` 与 `/xlpa` 路由前缀语义及会话模式保持不变

### Requirement: 输入区必须为一体化 composer 且附件可删除

前端输入区 MUST 为单一 composer 卡片，含附件 chip 行、自适应增高的文本输入与底部
工具栏（［＋］加文件、模型选择、发送/停止切换按钮）。已附加文件 MUST 以 chip 呈现
（文件名/缩略），每个 chip MUST 提供始终可见的 ✕ 删除入口（文件名截断 MUST NOT
裁剪 ✕），发送前 MUST 可逐个移除已暂存附件（移除发生在上传之前）。工具栏 MUST 保留
可选路由前缀提示，MUST NOT 强制前缀。

#### Scenario: 加文件呈现 chip

- **WHEN** 用户经［＋］附加一个文件
- **THEN** 附件行出现该文件 chip（文件名/缩略 + ✕ 删除入口），文件尚未上传解析

#### Scenario: 删除附件 chip

- **WHEN** 用户点击某附件 chip 的 ✕
- **THEN** 该附件从待发送列表移除、chip 消失，其余附件保留

#### Scenario: 多附件独立删除

- **WHEN** 用户附加多个文件后删除其一
- **THEN** 仅被删 chip 消失，其余附件仍可随消息发送

### Requirement: 移动端必须全视口沉浸布局

移动端页面 MUST 采用全视口 app-like 布局：主视图（会话列表 + 对话区）MUST 以
`position:fixed; inset:0` 脱离文档流占满视口，composer 吸底、消息区独立滚动、
适配 safe-area 安全区；文档级滚动 MUST NOT 作为主视图的布局手段——文档 MUST NOT
存在可被键盘弹起利用的滚动余量，顶栏（含移动端会话列表入口）MUST NOT 因文档
滚动偏移被推出视口。登录成功切换到主视图时与登出回登录页时，前端 MUST 复位文档
滚动偏移并使输入控件失焦（键盘收起兜底）。登录 MUST NOT 自动请求全屏——原生文件
picker 会强制退出全屏，自动全屏与上传冲突且体验跳动；沉浸感 MUST 由全视口布局
提供，MUST NOT 依赖 PWA/加主屏幕/HTTPS，MUST NOT 按操作系统硬分支。

#### Scenario: 全视口布局

- **WHEN** 用户在手机浏览器打开页面
- **THEN** 主视图占满视口且脱离文档流，composer 吸底、消息区独立滚动，无多余留白

#### Scenario: 登录切视图后顶栏完整可见

- **WHEN** 用户在手机浏览器（含 iOS 键盘已弹起的场景）完成登录进入主视图
- **THEN** 顶栏（含 ☰ 会话入口与退出按钮）完整可见，无需手动缩放或滚动找回，
  文档滚动偏移已被复位

#### Scenario: 键盘收起后不残留偏移

- **WHEN** 用户在主视图聚焦输入框再收起键盘
- **THEN** 顶栏仍完整可见，不出现整页被顶出视口的现象

#### Scenario: 能力检测全屏

- **WHEN** 用户点击登录
- **THEN** MUST NOT 自动请求全屏，保持全视口布局（避免后续文件 picker 退出全屏的跳动）

#### Scenario: 不支持降级

- **WHEN** 浏览器不支持全屏 API
- **THEN** 页面仍以全视口布局占满，无报错、不依赖全屏

#### Scenario: 桌面端行为不变

- **WHEN** 用户在桌面浏览器使用
- **THEN** 布局与既有行为一致（顶栏、侧栏、composer 各区不受本次布局手段变更影响）

### Requirement: 助手消息必须以富内容渲染呈现且渲染前必须消毒

助手消息文本 MUST 按 markdown 渲染为富内容呈现：标题、列表、表格、行内
代码与围栏代码块 MUST 渲染为对应的展示形态（表格为可读表格、代码为等宽
代码块）；围栏代码块 MUST 提供语言语法高亮与一键复制入口。```mermaid
代码块 MUST 渲染为图形（流程图/时序图/状态图）。全部由助手内容派生的
