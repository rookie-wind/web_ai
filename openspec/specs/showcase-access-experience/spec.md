# showcase-access-experience Specification

## Purpose

定义协议转换 MCP Server 的成果展示页与一键接入页用户体验，使展示、理解、接入和分发形成连续的产品化体验，并在不改变后端接口与鉴权边界的前提下提升视觉完成度、AI 价值表达和客户端兼容性。

## Requirements

### Requirement: 成果展示页必须呈现 AI 智能体驱动的价值叙事
系统 SHALL 在成果展示页中清晰表达协议接入由 AI 智能体辅助完成，并 SHALL 保留现有成品展示定位，不得将页面改造成需要老板做决策的方案评审页。

#### Scenario: 展示 Before/After 对比
- **WHEN** 用户浏览“同一件事，两种做法”区域
- **THEN** 页面必须保留该标题
- **THEN** 页面必须说明左侧为接入新设备协议的手工全过程
- **THEN** 页面必须说明右侧为交给 AI 智能体并通过一句话跑完全程

#### Scenario: 展示已交付能力
- **WHEN** 用户浏览展示页
- **THEN** 页面必须保留真实交付记录、回归测试和真实产出物区域
- **THEN** 页面不得将 48 个 MCP tools 逐个展开为架构图主内容

### Requirement: 成果展示页必须提供清晰有意义的数据流转架构图
系统 SHALL 以独立大尺寸模块展示协议智能体数据流转架构，说明从用户需求到可上线交付物的闭环，而不是将架构图作为首屏右侧小型装饰图。

#### Scenario: 浏览数据流转架构
- **WHEN** 用户滚动到数据流转架构模块
- **THEN** 页面必须展示用户需求、AI 智能体理解意图、协议识别与技能路由、MCP 工具网关、配置生成、测试验证、打包分发和上线运行之间的主路径
- **THEN** 架构图中文字在常见桌面展示宽度下必须清晰可读
- **THEN** 架构图必须避免展开 48 个 tools 的点阵或明细列表

#### Scenario: 理解交付闭环
- **WHEN** 用户查看架构图输出端
- **THEN** 页面必须表达配置生成、测试验证、打包分发和上线运行构成完整交付闭环
- **THEN** 页面必须让用户能区分协议识别、工具编排和交付产物三个层级

### Requirement: 首屏必须突出产品价值和运行感
系统 SHALL 将首屏组织为左侧价值叙事与核心数字、右侧放大终端会话，终端会话必须表现 AI 智能体接收自然语言协议分析请求并执行流程。

#### Scenario: 首屏加载
- **WHEN** 用户打开成果展示页根路径或 `/showcase`
- **THEN** 首屏必须显示标题、副标题、核心指标和放大终端会话
- **THEN** 核心指标必须包含 MCP 原子工具、领域技能、兼容 AI IDE 和协议方向
- **THEN** 终端命令必须使用“请帮我分析这份协议文档”的语义表达

### Requirement: 一键接入页必须与成果展示页保持同一视觉体系
系统 SHALL 将一键接入页呈现为与成果展示页一致的深色霓虹产品控制台，而不是浅色后台表单。

#### Scenario: 从展示页进入接入页
- **WHEN** 用户从成果展示页点击进入一键接入工具
- **THEN** 接入页必须使用深色背景、霓虹强调色、卡片化布局和代码/终端风格组件
- **THEN** 接入页必须提供无文字返回成果展示页入口
- **THEN** 接入页不得新增演示模式或全局运行仪表条

#### Scenario: 查看安全提示
- **WHEN** 用户查看接入页 Token 与权限信息
- **THEN** 页面必须以可视化方式提示 IP 绑定、权限分级、自动分配和请勿外传等 Token 安全要点

### Requirement: 接入页必须支持卡片式目标平台选择
系统 SHALL 将目标平台选择展示为卡片式入口，并 SHALL 支持 Trae、Cursor、VS Code Copilot、Claude Desktop、Windsurf、Cline、Kimi Code 和 Qoder。

#### Scenario: 选择目标平台
- **WHEN** 用户点击任一平台卡片
- **THEN** 页面必须将该平台设置为当前目标平台
- **THEN** 页面必须重新生成对应平台的接入配置
- **THEN** 页面必须显示已为当前平台生成接入配置的状态反馈

### Requirement: 接入文本预览必须以代码编辑器方式展示且复制下载保持纯文本
系统 SHALL 使用代码编辑器式预览展示接入文本，并 SHALL 保证复制和下载结果为无行号、无 HTML 标记的原始 Markdown 文本。

#### Scenario: 生成接入配置
- **WHEN** 页面获取到接入信息并生成接入文本
- **THEN** 页面必须显示代码编辑器式预览
- **THEN** 预览必须包含行号或等效的代码阅读辅助样式
- **THEN** 复制到剪贴板和下载文件必须使用原始接入文本

#### Scenario: 切换平台后复制
- **WHEN** 用户切换目标平台并点击复制或下载
- **THEN** 复制或下载内容必须反映当前平台
- **THEN** 内容不得包含预览层的行号、HTML 标签或视觉装饰文本

### Requirement: Qoder 平台配置必须使用 url 和 headers 格式
系统 SHALL 为 Qoder 生成 `mcpServers` 根键下的 MCP 配置，服务条目 SHALL 包含 `url` 和 `headers`，并 SHALL NOT 输出 `type` 字段。

#### Scenario: 生成 Qoder 接入配置
- **WHEN** 用户在接入页选择 Qoder
- **THEN** 生成的 JSON 配置根键必须为 `mcpServers`
- **THEN** `xl-protocol-agent` 服务条目必须包含 `/mcp` 结尾的 `url`
- **THEN** 服务条目必须包含 `Authorization: Bearer <token>` header
- **THEN** 服务条目不得包含 `type` 字段

### Requirement: 一键接入页必须回显当前客户端本次操作日志
系统 SHALL 在一键接入页提供"本次操作日志"展示区，凭页面已持有的接入 Token 定向拉取
并展示当前客户端自己在本次会话窗内的写操作日志；展示区 SHALL NOT 显示其他客户端的
操作日志，并 SHALL NOT 展示任何原始 Token、口令或验证码等机密内容。

#### Scenario: 展示自己的操作流水
- **WHEN** 客户端在完成登录或写操作后查看接入页日志展示区
- **THEN** 页面必须按时间列出该客户端本次会话内的操作名、结果状态与发生时间

#### Scenario: 无操作时的空态
- **WHEN** 当前会话尚无任何写操作日志
- **THEN** 页面必须显示明确的空态提示，不得显示他人或历史无关日志

#### Scenario: 跨身份不泄露
- **WHEN** 页面请求操作日志
- **THEN** 返回与展示内容必须仅匹配该页面接入 Token 派生的身份，不含其他身份的日志
