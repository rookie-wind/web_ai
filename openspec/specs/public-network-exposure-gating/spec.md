# public-network-exposure-gating Specification

## Purpose
定义系统（mcp_server 与 webchat）HTTP 端点在网络暴露模式下的访问门控
契约：展示类端点的访问范围收紧、URL 携凭据端点的非本机来源鉴权收紧、
登录限流所依赖的真实客户端标识，以及公网部署时必须满足的前置条件清单。
内网模式（默认）保持既有行为零变化。

## Requirements

### Requirement: 网络暴露模式必须默认关闭且开启为显式部署决策

系统 MUST 提供网络暴露模式开关，默认关闭。开关关闭时，所有既有 HTTP
端点的行为 MUST 与当前完全一致（内网零影响）。开关 MUST 仅由部署者
显式配置启用，MUST NOT 因检测到非本机访问等情况自动开启或改变行为。

#### Scenario: 默认关闭行为不变

- **WHEN** 未配置网络暴露模式且远程客户端访问展示类端点
- **THEN** 端点按既有行为响应（无需鉴权即可访问），不产生任何变化

#### Scenario: 显式开启

- **WHEN** 部署者显式开启网络暴露模式并重启服务
- **THEN** 本能力其余需求所述的门控对所有非本机来源生效

### Requirement: 公网模式下展示类端点仅对本机与显式 allowlist 放行

开启网络暴露模式后，无鉴权的展示与资产类端点（接入信息、成果展示数据、
Skills 导出、静态展示/接入页面）对**非本机来源** MUST 返回拒绝响应
（403/404 语义之一，不泄漏端点存在性细节），除非来源命中部署者配置的
显式 allowlist。本机来源（含环回与本机网卡地址）MUST 仍可正常访问，
保证运维与验收路径可用。

#### Scenario: 远程来源被拒

- **WHEN** 公网模式开启且非 allowlist 的远程 IP 请求展示类端点
- **THEN** 请求被拒绝，响应体不回显 allowlist 内容或 Token 信息

#### Scenario: allowlist 命中放行

- **WHEN** 部署配置的 allowlist 含某来源 IP 且该来源请求展示类端点
- **THEN** 端点按既有行为正常响应

### Requirement: 公网模式下 URL 携凭据端点的非本机来源必须补充鉴权

开启网络暴露模式后，以 URL 携带票据/归属摘要的下载端点（模板/产物
文件下载、操作日志回读）对**非本机来源** MUST 额外要求有效 Bearer
接入凭据，且凭据派生的归属 MUST 与请求的目标归属一致才可返回内容；
不一致或无凭据 MUST 拒绝且不泄漏资源存在性。本机来源 MUST 保持既有
票据下载行为（不破坏现有内网客户端与脚本）。

#### Scenario: 远程票据下载需凭据

- **WHEN** 公网模式开启且远程来源仅凭 file_id 与 owner 查询串请求下载
- **THEN** 请求被拒绝；附带有效 Bearer 且归属一致时 MUST 成功下载

#### Scenario: 本机票据下载不变

- **WHEN** 公网模式开启且本机来源以既有票据 URL 请求下载
- **THEN** 按既有行为返回文件内容

### Requirement: 公网部署前置清单必须落文档并可逐项核验

系统文档 MUST 提供公网部署前置清单，至少覆盖：对外形态与证书来源
（HTTPS 终止位置）、反向代理 SSE 关闭响应缓冲、真实客户端 IP 透传
（代理层独占信任 X-Forwarded-For，直连时忽略该头）、webchat 与
mcp_server 的暴露范围最小化（仅按需反代所需路径）、限流参数与
巡检项。清单 MUST 逐项给出可执行判据（命令或配置片段），验收时
逐项勾选留证。

#### Scenario: 伪造来源头不被信任

- **WHEN** 请求未经配置的信任代理而携带伪造的真实客户端 IP 头
- **THEN** 服务端按直连来源 IP 判定本机/远程，伪造头不改变门控结论

#### Scenario: 清单逐项核验

- **WHEN** 验收人员按部署清单逐项检查代理与 TLS 配置
- **THEN** 每项均有明确判据与验证结果记录，未通过项不得宣称公网就绪

### Requirement: 登录限流必须基于可信的真实客户端标识

登录失败限流 MUST 以可信的真实客户端标识作为计数维度。未配置可信代理时
MUST 使用连接的直连来源地址，MUST NOT 采信任何转发头；配置可信代理时
MUST 仅当直连来源命中该清单才采信转发头中的最左值，否则回落直连地址。
伪造转发头 MUST NOT 改变计数维度。

限流 MUST 保证跨来源隔离：单一来源的连续失败仅影响该来源自身，
MUST NOT 波及其他来源的合法用户。若同时存在不区分账号的来源级计数，
其阈值 MUST 显著高于账号级阈值，且 MUST 在文档中说明由此带来的同出口
网络（共享 NAT）用户互相影响的边界。

#### Scenario: 反代后不同来源互不影响

- **WHEN** 服务位于反向代理之后，多个不同真实客户端分别登录
- **THEN** 各客户端按各自真实来源独立计数；某一来源失败达阈值被限流时，
  其他来源的合法用户仍可正常登录

#### Scenario: 伪造转发头无效

- **WHEN** 直连来源不在可信代理清单内，却在请求中携带伪造的真实客户端 IP 头
- **THEN** 限流仍按直连来源地址计数，伪造头不改变判定

### Requirement: webchat 自身端点必须纳入暴露边界与部署清单

公网部署前置清单 MUST 同时覆盖 webchat 的端点暴露边界（登录与会话 API、
事件流、静态前端、产物上传与下载），并 MUST 给出 webchat 监听地址与
「由反向代理对外暴露」的分工说明及默认值。清单 MUST 明确 webchat 登录
接口在公网直连时的限流参数与巡检项；每项 MUST 附可执行判据。

#### Scenario: webchat 暴露范围可核验

- **WHEN** 验收人员按部署清单检查 webchat 的对外路径
- **THEN** 每一项均有明确判据（监听地址、代理转发路径、限流参数），
  未配置项不得宣称公网就绪
