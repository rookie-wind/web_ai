## Why

实测会话中反复出现两个体验问题：

1. **确认卡片出现得太晚**：用户请求读取边缘设备树时，Agent 先在聊天文本里索要
   账号/密码/验证码，用户把这些明文贴在聊天框后，Agent 才调用 `edge_get_token`，
   此时门禁才弹出确认/参数卡片。用户看到的是"输入密码之后才弹对话框"；同时
   Agent 还会引导用户"直接回复确认"，但后端确认只由卡片按钮触发，聊天回复
   `确认` 不会铸票，导致多次重试仍被拦截。
2. **未请求也生成文件**：任意超过 8000 字的工具结果被自动落盘为下载产物，
   例如 `list_mcp_tools` 的 14KB JSON 在用户没有要求生成文档时自动出现。

## What Changes

- **Web 交互系统提示**：在 CLI 默认系统提示后追加约定——受门禁工具（含
  `edge_get_token`）需要确认/凭据时，Agent MUST 直接调用工具（缺失参数可留空）
  以触发前端卡片，MUST NOT 在聊天中索要密码/验证码，MUST NOT 要求用户以聊天
  回复"确认"作为授权。卡片提交后由既有 confirm + 续跑链路完成。
- **移除工具结果自动落盘**：删除"超过阈值即落盘为产物"的逻辑；产物只来自
  Agent 显式写入 `xlpa-output/` 与白名单 MCP 工具的 `file_id` 原生交付。
- 前端工具结果截断文案去掉"可下载完整文件"的误导提示。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-runtime-session`: 新增"确认与凭据收集必须由前端卡片先行"要求。
- `web-artifact-delivery`: 新增"产物必须由显式请求或原生产物产生"要求。

## Impact

- **webchat 后端**：`sdk_runtime/adapter.py`（系统提示追加）、`runtime.py`（删除
  大结果自动落盘与相关常量/辅助函数）。
- **前端**：`static/js/app.js` 仅调整截断文案；确认卡片逻辑不变。
- **mcp_server**：零改动。
- **测试**：新增"大结果不自动产生产物"用例与系统提示断言；原大结果导出用例替换。
- **行为变化**：工具结果不再提供完整文件下载；需要完整数据时由 Agent 显式写入
  产物目录。会话确认交互更前置，用户无需在聊天粘贴凭据。
