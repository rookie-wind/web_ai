## Decisions

### D1 用系统提示把确认动作前置到卡片

- `AdapterConfig` 不需要新增字段；在 `_build_options` 的 `system_prompt` 使用
  CLI preset + `append`，只追加 Web 交互约定，不替换默认提示。
- 约定内容：直接调用受门禁工具（缺失参数可留空）→ 系统自动弹卡片；不要在聊天
  索要密码/验证码；不要让用户回复"确认"；卡片提交后自动续跑。
- 这样 `edge_get_token` 会在用户提供凭据之前就被调用一次，门禁立即产
  `gate_blocked` 并渲染参数表单，用户在卡片里填写敏感字段（掩码、不回显、不进
  聊天历史）。

### D2 工具结果不再自动落盘

- 移除 `_maybe_export_large_result` 与 `LARGE_RESULT_EXPORT_THRESHOLD`；不再因
  结果大小产生产物。
- 保留来源 A（Agent 显式写入 `xlpa-output/`，turn 收尾扫描）与来源 B（白名单
  MCP `file_id` 回源），两者都是用户任务实际需要的产物。
- 前端工具结果仍按 20000 字截断展示，只去掉"可下载完整文件"文案。

### D3 不改确认与票据机制

- 确认仍只能由卡片按钮调用 `POST /confirm`；不新增"聊天回复确认即铸票"的路径，
  避免把任意聊天文本当作授权。
- 不改 `edge_get_token` 的 provision 分类与 TTL 窗口语义。

## Risks

- 系统提示可能使 Agent 在信息不足时也先调用工具，产生一张待确认卡片；这是预期
  交互（卡片本身就是收集参数的入口），用户可忽略或填写。
- 移除大结果导出后，超大工具结果只能在事件气泡中截断查看；完整事件仍持久化在
  事件文件，但不再提供下载入口。
