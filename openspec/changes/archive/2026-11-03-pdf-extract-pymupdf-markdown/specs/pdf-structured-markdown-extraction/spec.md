## Purpose

定义文档通道对 PDF 内容的结构化抽取契约：把含表格的 PDF 转成机器可读、
位置可追溯的 Markdown 文本，供会话内 Agent 直接读取，避免表格信息在
抽取过程中丢失。

## ADDED Requirements

### Requirement: PDF 抽取必须保留表格结构

PDF 抽取产物 MUST 为 Markdown 文本：文档中的表格 MUST 以 GFM 表格
（表头行 + 分隔行 + 数据行）呈现，单元格内容 MUST 与其在原版面中的
列位置对应，MUST NOT 把同一行的多列数据串接成单列文本。无法判定
表头的表格 MUST 仍输出完整行列结构（可用占位表头），MUST NOT 丢弃。

#### Scenario: 带框线的寄存器点表

- **WHEN** 抽取一份含带框线多列寄存器表的 PDF
- **THEN** 产物中该表以 GFM 表格呈现，每行单元格数与原版面列数一致，
  地址/名称/类型等列不串位

#### Scenario: 表格与正文共存于同页

- **WHEN** 某页同时含说明文字与表格
- **THEN** 产物中该页正文与表格分别出现，表格区域的文字 MUST NOT
  在正文段与表格中重复出现

### Requirement: 抽取产物必须位置可追溯

抽取产物 MUST 按 PDF 物理页组织，每页 MUST 有可定位的页级锚点，
使后续产物能标注"来源第 N 页"以支持人工核对。页内表格 MUST 可被
区分（如带表序号与行列数），MUST NOT 多表合并为一张表。

#### Scenario: 跨页多表

- **WHEN** 同一 PDF 的多页各含多张表格
- **THEN** 产物中每张表独立出现并归属其所在页锚点，行列数随表标注

### Requirement: 抽取失败必须显式降级且依赖可缺失

抽取 MUST NOT 阻塞上传响应；依赖缺失、文件无法解析、未抽取到任何
文本层、写盘失败时 MUST 返回可辨识的显式告警并保留原始 PDF，
MUST NOT 产出空文件冒充成功，MUST NOT 凭记忆或占位内容伪造点表。
抽取组件未安装时上传链路 MUST 仍可正常工作（仅降级为告警）。

#### Scenario: 扫描件无文本层

- **WHEN** 上传的 PDF 没有任何文本层
- **THEN** 不生成抽取文件，事件载荷含说明"可能为扫描件"的告警

#### Scenario: 抽取组件缺失

- **WHEN** 运行环境未安装 PDF 抽取组件
- **THEN** 上传仍返回 200 且原文件保留，事件载荷含组件未安装的告警

### Requirement: Agent 侧必须被引导读取抽取产物

Agent 直接读取工作区内的原始 PDF 时，系统 MUST 拒绝该读取并给出
指向抽取产物路径的替换提示；提示中的文件名 MUST 与实际落盘的抽取
文件名一致。抽取产物缺失时 MUST 引导 Agent 稍后重试或如实告知用户，
MUST NOT 允许其以二进制 PDF 的猜测内容继续生成配置。

#### Scenario: 读取原始 PDF 被拦截

- **WHEN** Agent 调用读取工具指向工作区内的 `.pdf` 文件
- **THEN** 该调用被拒绝，拒绝原因含同名抽取产物的完整文件名

#### Scenario: 抽取尚未完成

- **WHEN** Agent 在后台抽取完成前尝试读取抽取产物
- **THEN** 系统如实说明未完成，Agent MUST 重试或告知用户，不得编造内容
