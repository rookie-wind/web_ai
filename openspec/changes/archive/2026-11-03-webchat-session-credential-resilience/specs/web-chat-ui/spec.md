# web-chat-ui Delta

## MODIFIED Requirements

### Requirement: 写入确认卡片必须呈现参数摘要且未确认零写入

当前端收到**可确认解除**的 gate_blocked 事件（写入门禁已拒绝一次调用，事件
携带工具名与参数摘要，`confirmable` 非 false）时，前端 MUST 弹出确认卡片
**并暂停本轮进度指示**，卡片 MUST 展示将执行的操作名与
**关键参数摘要**（如品牌/型号/计划标识/影响台数），使用户确认的对象与
模型将提交的对象一致；一键建档类操作的摘要由后端按计划域数据反查
获得（非仅工具入参），反查不足时卡片明示"摘要不可用，仅显示计划
标识"。绝对禁止类与护栏自纠错类拦截（`confirmable` 为 false，如业务登录、
内置读越界）确认亦无法解除，MUST NOT 弹出会暂停进度的确认卡，而 MUST 降级
为一行弱提示（不打断转圈、不进待确认队列）。用户点击确认前，系统 MUST
不发生任何平台写入（后端门禁保证，前端不得预铸造票据）。确认动作
MUST 调用既有 confirm 端点铸票，并 MUST 在事件流中可见确认结果；
用户拒绝或不操作时写入 MUST NOT 发生。

确认所用端点 MUST 遵守后端写租约前置：当前连接未持有写租约时，前端
MUST 先获取租约再发起确认，MUST NOT 把租约冲突（409）当作业务失败
提示用户；租约过期时 MUST 能重新获取并重发确认。

#### Scenario: 确认卡片含参数摘要

- **WHEN** agent 请求执行建档写入
- **THEN** 卡片展示操作名与关键参数摘要，用户确认后写入才执行，
  事件流出现确认通过记录

#### Scenario: 未确认零写入

- **WHEN** 确认卡片出现后用户关闭页面未确认
- **THEN** 对应写入未发生，后续同目标写入请求被门禁拦截

#### Scenario: 租约缺失时先取租约

- **WHEN** 用户点击确认而当前连接已不再持有写租约
- **THEN** 前端先重新获取租约再调用确认，最终确认成功，不向用户展示
  租约类错误文案

#### Scenario: 绝对禁止类拦截降级为弱提示不暂停进度

- **WHEN** 前端收到 `confirmable` 为 false 的 gate_blocked 事件（如业务登录、
  内置读越界）
- **THEN** 不弹出会暂停进度的确认卡，改呈现一行弱提示，本轮转圈与执行
  不被打断，事件流仍保留该拒绝记录
