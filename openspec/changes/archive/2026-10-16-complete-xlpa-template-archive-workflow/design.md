## Context

动机见 [proposal.md](proposal.md)。本设计承接前序建档引擎，但不把已有局部实现或历史实测当作新流程完成证据。

已核对的实现约束：
- `archiving/templates/generator.py` 与 `excel_reader.py` 仍使用 `v6-engineer`；v14草案生成脚本不能直接发布，其中有历史现场数据、固定默认值、未绑定的下拉和未确定映射。
- `profiles/meter_xlba.py` 分别构造档案与下发参数，存在空白补默认、未知名称透传、固定 `feeNum` 和空 `extInfos`；`edge_tools.py` 还会补测量点号并静默跳过无法下发的条目。
- `engine.py` 的业务身份索引会保留首个候选，尚无网关内两个编号的独立冲突检查；原子写入工具也未强制遵守引擎的 SKIP 决定。
- `read_device_archive_template` 接收服务端路径，`EdgeSessionStore` 没有调用者隔离或到期机制。现有 `CompositeApp` 的公开文档下载分支不能直接承担敏感工作簿回传。
- `server.py` 已有 MCP Token 上下文、系统云端 Token 和刷新机制；通用平台调用会回退到用户会话。云端客户端使用 `Token` 请求头，边缘客户端另有登录和签名，不可混用。
- 时钟端点已验证使用 `devId`，现有工具仍用 `deviceId`。现有监测点工具调用 `callDeviceData`，不是已指定的旧协议 `31800008` 运维契约；HTTP客户端尚未保留HTTP状态。

## Goals / Non-Goals

**Goals:**
- 让模板、解析、计划、payload及回读验证共享一份版本化字段契约，消除各层独立补默认和映射漂移。
- 将文件、快照、任务、确认和设备归属绑定；服务端实施守卫，Skill负责可见的原子步骤编排。
- 对暂未获得设备侧证据的字段和接口设置具体发布门槛，并定义无法验证时的安全结果。

**Non-Goals:**
- 不引入数据库、任务队列、对象存储或任意插件代码执行；首版采用单进程服务与本地非敏感快照存储。
- 不实现已有档案更新、跨父迁移、隐式全量下发、自动补编号、校时或自动清理设备。
- 不在本次规划中修改代码、Excel、前序变更、主规范或现场环境。

## Decisions

### 1. 固定参考字典提供器与现场客户端分离

在 `archiving/` 增加参考字典提供器，供模板生成工具使用，不建立现场 `EdgeSession`。

配置采用独立的 `XLPA_REFERENCE_EDGE_URL`、`XLPA_REFERENCE_EDGE_LOGIN_NAME`、`XLPA_REFERENCE_EDGE_PASSWORD`；云端沿用 `PCA_API_BASE_URL` 与现有系统 Token 管理器。配置中只保存管理员提供的来源，不预置175或23地址、账号、密码。生成请求不允许调用者覆盖参考地址。

云端调用只允许系统 Token，失效后刷新一次再重试，失败即报告参考认证不可用；不调用会回退用户 `fallback_token` 的通用链。参考边缘客户端采用现有签名登录，按一次生成任务管理生命周期，与现场连接完全隔离。

| 字典 | 已知取数契约 | 业务码值用途 |
|---|---|---|
| 设备类型 | 参考边缘 `getDeviceTypeSelect` | `code → deviceTypeId` |
| 用户大分类 | 云端 `get_device_type_list` | `deviceTypeCode → userBigNo` |
| 品牌 | 云端 `get_brand_list` | `code → brand` |
| 型号 | 云端 `get_model_list`，保留品牌关联 | `modelCode → decimalNum` |
| 代理通信方式 | 参考边缘 `getDictItemList`，`dictTypeCode=CommunicationMode`，路径不追加 `/v1` | `dictItemCode → proxyCommType` |

每次生成重新取数；各适配器显式处理总数、分页和结束条件，检测重复页、截断及同作用域同名异码。原始列表标准化为带来源、作用域、名称、码值和获取时间的记录。接口内部ID仅可用于查询关联，不替代业务码。字典保留全量，注册表独立限制可执行类型。

选择理由：复用已有认证实现而不改变参考来源。未选用户登录回退、从上传工作簿取参考地址或旧缓存降级，这些方式会改变“固定参考环境的最新字典”含义。

### 2. 快照与字段契约共同构成模板解释依据

复用并扩展 `models.py` 的字段模型与 profile 注册表，每种类型声明：sheet名、设备类型码、列名和稳定字段键、输入类型、必需条件、字典作用域、各阶段落点、派生依赖、读回路径、接口能力及证据状态。

字段来源分为 `ENGINEER_INPUT`、`PROTOCOL_CONSTANT`、`DERIVED`。控制任务超时和允许标志属于执行策略，不伪装成设备工程值。缺省下发／召测权限为关闭；请求25秒、联通12秒是现有传输策略的初始值，在元数据及计划中明确展示，不写入设备参数。

生成器、reader、profile、payload构造器与回读比较器均消费该契约，不各自维护名称码值表。结构分为：
- `TemplateSnapshot`：版本、字段契约版本、快照ID、来源时间、完整字典及映射、规范化内容摘要。
- `CellInput`：原始标量、是否填写、规范化值、工作表／行／列、映射来源。
- `ResolvedField`：字段键、来源分类、已确定值和档案／下发／读回表示；不适用的落点须显式声明理由。
- `ProfileResult`：按动作输出已解析字段、错误及前置条件；没有“未填就用默认”的通用分支。

快照和生成的空白模板只含非敏感内容，保存在服务私有状态目录 `archive_templates/`，不进入git或Skills包。随机快照ID、所属接入身份、生成文件摘要、字段契约及规范化字典内容组成服务端权威记录，默认保留30天，过期明确要求重取模板。工作簿可查看字典／映射，但服务端核对其规范化内容与权威快照；不对整个已填写文件做原模板字节相等检查。

选择理由：服务端权威快照能够区分合法填表与改码，且无需新的签名密钥体系。未选“信任Excel映射”或“建档时重查最新字典”，避免篡改和选项语义漂移。首版不支持跨调用者分享工作簿快照；需要分享时重新获取，不放宽文件归属。

### 3. 通过受控HTTP文件通道交付，不将敏感文件塞入MCP文本

新增MCP能力及路由，名称在本设计中固定：

| 入口 | 行为及返回 |
|---|---|
| `generate_device_archive_template()` | 取字典、生成文件，返回 `file_id`、文件名、大小、SHA-256、版本、快照ID、到期时间及下载URL |
| `get_device_archive_template_download(file_id)` | 校验调用者归属及模板有效期，重新签发15分钟下载票据 |
| `GET /api/archive/templates/{file_id}?ticket=...` | 只允许下载未填写的生成模板；验证短期票据、关联身份仍有效及文件状态 |
| `POST /api/archive/uploads` | MCP Bearer鉴权，接收原始XLSX字节及 `X-Content-SHA256`，返回调用者隔离的 `file_id`、大小和摘要 |
| `read_device_archive_template(file_id)` | 从受控上传存储读取，校验快照、解析并创建有归属的任务；不再接受远程任意 `excel_path` |
| `get_device_archive_task_report(task_id)` | 按调用者归属读取脱敏计划、动作证据与补偿清单；任务到期后只读可查，不恢复执行权限 |

`CompositeApp` 将上传路由接入与MCP相同的Token校验；下载路由单独校验受限票据，不能落入公开静态目录。票据为高熵随机值，服务端只存摘要，绑定文件、身份、用途和到期时间。URL不含长期Token，访问日志剔除票据，响应设 `Cache-Control: no-store`、`Referrer-Policy: no-referrer` 和正确附件文件名。下载仅匹配生成文件类别，永不提供已填上传文件的下载入口。

在现有 `agent_assets/skills/xlpa/tools/mcp_client.py` 增加文件上传／下载子命令，作为不具备二进制附件传输能力的客户端适配：只接收本地路径及明确的MCP服务配置名，程序内部读取该服务Token，上传文件流，输出文件引用或下载后的本地路径和摘要。不得把Base64、密码或Token送入工具文本、命令行参数或日志；不得采用“第一个server配置”或对所有server回写Token。401时停止并提示重新接入，不能更换身份后继续访问旧文件。原生附件客户端也必须通过同一受控上传接口取得引用。

服务公开下载地址来自 `XLPA_PUBLIC_BASE_URL`，不信任请求的任意Host拼接链接。远程含凭据上传要求HTTPS入口，环回开发可使用HTTP；服务启动应提示反向代理也必须关闭请求体日志及敏感上传的落盘缓冲。

选择理由：既有ASGI和客户端辅助脚本即可完成远程交付，不需要新文件平台。未选仅返回服务端路径、把填表内容编码到MCP文本或新增公开上传页。

### 4. 敏感上传、任务与资源限制

上传在有界内存中暂存，不使用可能自动落盘的上传缓冲；默认15分钟过期，成功解析后释放原始字节。解析失败可以重新上传，不能泄露含密码的行内容。现场凭据只进入任务内存；任务闲置2小时或创建8小时后失效，关闭边缘客户端并释放引用。首版重启丢失上传和任务，用户重新上传／计划；不得自动恢复未完成写入或重发下发。

脱敏计划、动作状态和补偿清单单独存入私有 `archive_reports/`，保留归属和任务ID而不保存现场凭据、原始Excel或登录响应；动作发送前记录意图，返回后原子更新结果。进程中断留下的未完成意图保持“结果未明”，不转为成功或自动重发。此类报告不随内存任务到期清除，通过只读报告工具取得；客户端本地输入Excel始终不自动删除。既有“保留输入”的条款在新delta中明确区分用户原件与服务端短期敏感副本。

文件和任务的所有者由已验证MCP Token的不可逆身份摘要派生，不使用IP、云端角色或用户传入字段。`register_edge_tools` 接收身份解析回调以避免反向导入 `server.py`；所有原子查询、写入、召测、补偿及计划工具统一检查任务归属，随机ID本身不等于权限。任务内使用锁序列化状态变化。

初始限制固定为：单文件10 MiB、ZIP条目2048个、总解压64 MiB、单条目解压比不超过100、单用户最多2个待解析上传、全局上传原始字节上限128 MiB；越限返回明确错误，可由管理员配置调整。解析前检查真实OOXML结构、压缩元数据及实际读取上限，拒绝加密包、宏、重复条目、路径穿越、嵌入对象与外部工作簿关系。解析并发使用有界工作池，避免阻塞ASGI循环和耗尽内存。

选择理由：当前单进程会话模型适合有界内存保存短期现场秘密；不引入含凭据长期缓存或数据库。内存释放不宣称是可证明的安全擦除，宿主机转储、备份和代理日志仍需部署控制。

### 5. v14工作簿布局、实际下拉与无默认解析

工作簿按spec的六张表生成；其他设备类型通过注册新profile增加独立sheet，而不是增加XLBA条件分支。`系统连接` 分隔只读元数据与可填连接／执行策略区；设备数据行及现场IP、端口、账号、密码初始为空，不含样例设备或参考环境连接。元数据含支持的数据行数及快照有效期。

工程输入区域预设第2～10001行，共10000行。以命名区域引用字典，不使用超过Excel长度限制的内联列表；品牌显示名映射到稳定的内部品牌区域名，型号通过辅助公式／命名区域级联，避免中文、空格或数字开头品牌名成为非法范围名。品牌无型号时使用空范围。辅助列可隐藏，但不新增第七张业务表。服务端仍检查粘贴到声明范围以外的非空行，达到文件安全上限时明确拒绝，不静默丢行。

四项串口枚举的已知协议码：波特率 `38400→0、115200→1、1200→2、2400→3、4800→4、7200→5、9600→6、19200→7`；停止位 `1→0、2→1`；校验 `无→0、偶→2、奇→3`；数据位 `5→0、6→1、7→2、8→3`。旧协议还允许校验码1表示无校验，作为读回等价码保留出处，UI不创建同名异码选项。以上码值并不自动证明所有档案／下发落点相同，须按第10节门槛核验。

reader保留单元格类型，不以 `value or default` 判空；None或纯空白文本才标为空。0、"0"、False先保留，之后由字段类型判断是否合法。整数编号使用严格整数解析，接受1.0但拒绝1.5、NaN和无穷，不使用 `int(float(...))` 截断。条码和地址列设置文本格式，丢失的前导零不得猜补；密码保持原始文本，不用通用 `strip()` 改写。

公式只允许在生成器声明的辅助区域且与快照契约一致；工程输入单元格公式明确拒绝，避免 `data_only=True` 将未计算公式误判为空。重复表头、缺列、非空未知列、重名设备、关系缺失／多父／环都有单元格定位。Excel样式或列宽变化不视为映射篡改。无效模板不创建可执行任务。

选择理由：集中契约和服务端校验比依赖Excel校验更可靠。未选直接发布草案、旧版本静默转换、按通讯选项清空字段或借UI渲染补空扩展项。

### 6. 档案、扩展项和下发分别编码，共享填写状态

各落点从同一 `CellInput/ResolvedField` 生成，不从一个payload猜出另一个payload。已确认关系包括：设备类型固定码；网关条码转换；XLBA原地址；品牌码、型号码和用户大分类码；电流变比 `extInfos.cT`、电压变比 `extInfos.pT`；分路号档案 `agentNum` 与下发 `roadNo`；测量点号档案 `measuredPointNum` 与下发 `measurNo`。其余字段按契约核验表补齐，不复制历史默认字典。

`extInfos` 只序列化存在的有效工程值／确定派生值为 `{propertyCode, propertyValue}`。`dsTypeId` 仅在设备类型和用户大分类均确定时按已核验关系派生。`protocolCode`／`protocolNumber` 等名称相近的不同落点分别声明类型与来源，用户填写协议代号不能被固定200覆盖。

旧协议 `20200002` 的空调相关备注定义 `feeNum` 串口位域：`(baud << 5) | (stop << 4) | (check << 2) | data`。例如115200、1位停止、无校验、8数据位得到35。此转换仅由明确适用的类别／协议能力启用，四项依赖不完整时不猜补；若该操作确实要求该组合字段则阻止该操作并列出缺项。其他类别不可因历史 `feeNum=195` 沿用该规则。

对已填写但某操作无落点的字段，契约须说明它属于其他阶段；若承诺有落点却未实现，阻止该阶段，不静默丢弃。部分参数不足以满足后端完整结构时标记前置条件不足，不通过回填历史值或后端值代替工程输入。

选择理由：共享输入而不共享未经区分的输出，能兼顾档案和协议不同表示；未选通用字典透传、全类型共用位域或空项补全。

### 7. 身份、归属和两个编号使用独立索引

dry-run先解析业务身份，再读取目标树与详情，取得相关网关的完整设备集合、实际父级、条码、分路号及测量点号。以现有 `getDeviceTree`、`getDeviceList`、`getDeviceListByPId` 为读取适配器基础，分页及字段完整性由契约测试确定；树上没有字段时必须回查，不将缺数据当作空集合。

身份索引保留候选列表：网关按条码，XLBA按条码＋严格规范化的分路号；多个后端候选即冲突。工作簿条码仍须唯一，以条码作为节点键；挂载表的名称只用于唯一关联到明细节点，不作为幂等键。

编号索引分别为 `(gateway_key, road_no)` 和 `(gateway_key, measured_point_no)`。已有网关使用实际deviceId，新网关在取得ID前使用本任务稳定条码键，取得ID后重新关联。SKIP节点去重后只以实际后端记录参与占位；已填值与实际值不同单独报告，不把同一设备计成两个冲突者。不得用计划值覆盖SKIP实际父级和编号。

两索引只比较同名字段；A=(分路1,测量2)、B=(分路2,测量1)合法。跨网关重复合法。对字段或所属网关不完整的后端记录标记“校验未完成”，阻止受影响网关写入／下发。空白测量点号在写前不占位，写后回读实际默认并重查；冲突时停止该网关后续阶段，不自行分配新号。

选择理由：身份幂等与网关编号是不同约束，不能用任一替代另一。未选全局唯一、只比较编号二元组或 `setdefault` 任取首个候选。

### 8. 计划绑定与原子执行守卫

`plan_device_archive` 返回不可变 `plan_id`、规范化摘要、字段来源、CREATE／SKIP／CONFLICT、实际父级、待下发集合及各阶段可执行性。计划绑定上传摘要、快照、节点输入和相关后端状态，不能把 `ok=True` 与“无冲突”混为一谈。含冲突的相关网关不允许执行；用户可对无冲突子集重新生成并确认计划。

写入类原子工具保留现有名称，但增加 `plan_id` 与 `confirm`，在服务端校验计划、调用者、节点、阶段和允许标志；下发额外绑定该网关的显式 `node_keys` 与payload摘要。计划或集合变化后重新确认。Skill在用户确认后才传递confirm，工具参数不等于可绕过计划的通行证。

执行按网关顺序串行：
1. 写前重新读取身份和编号占用；外部变更使计划失效则停止并重做计划，不自动改变CREATE为UPDATE。
2. CREATE调用不带deviceId的 `modifyDevice`；ID只从已验证响应字段或唯一业务身份回查取得，不能把任意响应字典转成字符串当ID。
3. 仅本任务新建节点调用 `updateDeviceParent`，参数为 `deviceId/parentId`；SKIP节点不挂载、不修正。
4. 挂载成功后带deviceId重发已确认的必需结构及实际填写的编号；该内部修正仅允许本任务已记录的新建ID。未填扩展字段不补空。
5. 回读父级、编号及全部已填写档案字段，逐项比较规范化结果。修正失败或差异使该阶段失败，不能仅追加布尔附注而维持顶层成功。

任务记录每步状态及本次新建ID。相同已成功动作的重复调用返回记录，不再次写入；超时动作标为结果未明，先只读回查，无法确认时停止，不盲目重发。任务内和同一目标网关进程内锁减少并发竞争；外部客户端仍可竞争，靠执行前／写后回查发现，不宣称有后端事务保证。

下发构造使用已确认的非空明确集合，逐条验证归属和payload；任一条目错误阻止整批，不 `continue` 丢条目，不补编号，不增加后端其他设备。SKIP仅跳过建档，可经独立确认参与下发；其实际父级或实际编号与本次输入不一致时不得自动改档，阻止相关批次并报告。

选择理由：保留原子审计模式，但将重要限制从Skill文字下沉到服务端。未选黑盒一键执行、重跑即更新、自动重试具有副作用的请求或自动补偿。补偿只列本次新建设备，另行明确确认后执行。

### 9. 分阶段通信结果与旧协议适配

`EdgeDeviceClient` 在解析JSON前保留HTTP状态；非200、非法JSON、业务错误与传输异常分别归一化。结果统一包含 `stage`、`status`、`http_status`、`rtnCode`、`rtnMsg`、`item_id`、`finish_flag`、目标网关／监测点／分路、起止时间、脱敏摘要和证据。`ok` 只由该阶段成功规则派生，不直接复制业务码结果。

阶段状态为 `NOT_RUN / BLOCKED / SUCCEEDED / FAILED / UNVERIFIED`，原因码保留 `NOT_CONFIGURED`、`OFFLINE_TIMEOUT` 等。超时和仅收到受理均为未验证，不自动断言设备离线或重发写请求。

完整编排顺序：建档／挂载／全字段回读 → 网关时钟 → `20200002`批量下发 → 逐监测点`31800008`召测。每阶段分别记录，依赖阶段未成功则后续阻止；关闭允许标志仍显示未执行，不改为已完成。单独诊断需独立确认目标范围，不补做未授权前序写入，也不计入完整流程验收。

- 时钟：修正 `edge_call_clock`，移除猜测 `item_id` 参数，请求 `POST /devArchManager/clock/action/callClock/v1`，body仅为 `{"devId": "<实际网关ID>"}`。HTTP200、rtnCode=0且 `rtnData.callTime.clockTime` 可解析才成功。只召测，不校时。
- 监测点：新增 `edge_call_monitor_debug(task_id, node_key, plan_id, tag="", confirm=False)`，由类型适配器取得已核实的请求设备ID与分路。目标数据项固定 `31800008`，`annexInfo={"roadNo": <整数>, "tag": ""}`；指定tag则按目标标签核验。旧 `edge_call_device_data` 仍可作为独立旧能力，但不得计入新链路通信证据。
- 运维入口候选为 `/sysConfigServer/comm/get/callDeviceParam/v1`，只有第10节验证入口与deviceId归属后才能启用；不可把样例ID或推测网关层级写死。
- 运维成功同时要求HTTP200、rtnCode=0、返回itemId=31800008、`finshFlag=0`、目标roadNo匹配、有效dataTime和目标数据。0／False数据不是空。保留混合端口日志供诊断，不用是否出现ERROR词决定通信结果。
- 时间有效性由适配器按设备时间域核验：使用本次网关时钟与请求耗时建立时间参考，不能直接与未同步的服务端时钟比较；诊断缺少可证明本次数据的时间或关联证据时为UNVERIFIED。允许的时间精度误差由已核验协议契约声明，不能用历史样例时间冒充新结果。
- 首版不猜异步补取端点。若目标服务返回未完成，只有已核实的只读结果接口及关联键可在任务联通时限内轮询；无该契约或超时则UNVERIFIED。禁止轮询时重新发送下发命令。

选择理由：HTTP、业务受理、协议完成、目标数据是不同证据层。未选HTTP200即成功、沿用31800006样例或把历史175成功作为此次全链路成功。

## Risks / Trade-offs

- [参考字典依赖多个服务，可能部分失败] → 生成采用全有或全无结果，返回具体来源；历史快照用于解释已发模板，不充当最新模板降级来源。
- [30天快照与单进程内存任务有生命周期限制] → 返回到期信息，解析前明确验证；支持重新获取下载票据，过期／重启后重新上传与计划，不恢复副作用请求。
- [Excel保护不是安全边界，公式可能无缓存] → 服务端验证映射及结构，只接受工程区域字面量；明确拒绝而非默认补值。
- [后端强制默认、参数省略或20200002集合语义与需求不符] → 按G2／G4阻断并报告；不能以“兼容”为由偷偷覆盖空白工程字段。
- [外部并发修改可绕过本进程锁] → 写前重查、写后验证、归属和编号冲突可见；不承诺跨客户端事务，发生竞争则停止后续动作。
- [错误响应、原始Excel和通信日志可能含敏感数据] → 输出字段白名单、凭据脱敏、限制响应摘要长度；原始上传不进报告，辅助工具不回显Token或原始文件。
- [模板/工具接口升级会影响旧客户端] → 与Skill资源一起版本化发布；旧模板和旧路径调用返回迁移提示，不做隐式兼容。
- [23门户阻碍浏览器操作] → 不将门户修复纳入此变更；按已授权通道核验协议，无法核验时保留阻塞状态。用户提供的报文只作结构样例。
