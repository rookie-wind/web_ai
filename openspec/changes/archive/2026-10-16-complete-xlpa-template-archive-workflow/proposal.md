## Why

当前正式实现仍是 `v6-engineer` 六表解析和有限默认值映射，尚未把“获取最新模板 → 工程人员现场填表 → 服务端建档 → 下发与通信验证”连成可交付流程。需要在已有 8163／XLBA 建档、条码幂等及挂载修正基础上，落实 v14 参考模板、完整下拉与只赋值已填参数的最新要求，避免把局部成功或响应样例当作整链路验收。

## What Changes

- 新增 `/xlpa 获取模板文档` 路径：服务端从配置的固定参考环境读取最新字典，生成并交付 `设备建档模板_YYYYMMDDHHMMSS.xlsx`；取模板不要求工程人员提供现场凭据或云端业务登录信息。
- 新增模板下载及填表后回传的受控文件通道；服务端文件路径不再被当作远程用户已收到文件的证据。现场连接信息只从回传工作簿读取，与参考环境凭据隔离。
- **BREAKING** 远程解析改用受控 `file_id`，不再接收任意服务端路径；执行工具绑定计划与目标确认。文件和任务按调用者隔离，短期敏感副本到期释放，脱敏审计独立保留，用户本地输入文件不自动删除。
- **BREAKING** 生成器和解析器切换为 `v14-engineer`：`系统连接 / 字典 / 挂载关系 / 网关·8163 / 监测点·XLBA / 映射`。v14 草案是结构参考，不直接复用草案中的现场凭据、默认数据、缺失下拉或 TBD 映射；旧模板被明确拒绝并提示重新获取，不做静默猜测转换。
- 设备类型分别声明 sheet、字段、字典依赖与接口能力；首期仅实现 8163 网关和 XLBA 监测点，其他类型保留扩展位。
- 补齐波特率、停止位、校验位、数据位的可选值、实际 Excel 下拉和各落点映射；品牌与型号保留级联和消歧。全部工程字段必须具有可追溯的解析、档案／下发落点与验证记录。
- **BREAKING** 工程参数仅映射、提交实际填写的部分：空白不补默认、不写空值覆盖，合法的 `0` 保留；不增加通信端口切换后强制清空“不适用参数”的拦截。协议固定字段与可追溯派生字段单独声明，不能冒充工程默认值。
- 同一网关内分别校验分路号、测量点号不能重复，不同网关可重复；覆盖表内计划与目标网关已有档案。保留网关按条码、监测点按条码＋分路号的幂等键，以及命中 SKIP、不更新、不迁移已有设备的规则。
- 保留并核验“新建 → 挂载 → 恢复已填写编号 → 回读”；只批量下发已确认的本次目标集合，不隐式扩成后端全量设备。
- 完整流程分别记录建档、网关时钟召测、档案批量下发、监测点运维调试召测。时钟使用已验证的 `devId` 请求；运维召测按旧协议 `31800008`，HTTP 预期 `200`，并继续核对业务码、完成标志和目标分路有效数据。
- 175“测试网关3”时钟成功作为历史单项证据；23 报文仅为响应样例，`31800006`、样例设备 ID 和读数不作为实现契约或本次实测结果。旧协议实际调用、请求设备归属与未闭环字段列为有明确退出条件的技术核验项。

## Capabilities

### New Capabilities

- `xlpa-archive-template-delivery`: 固定参考环境取参、动态工作簿生成、受控下载与回传，以及 `/xlpa` 两阶段入口和凭据隔离。

### Modified Capabilities

- `xlpa-device-archiving-workflow`: 原生模板及版本契约、字段映射与空白语义、网关内编号冲突、类型扩展、挂载修正、批量下发范围和分阶段通信验收。

此能力沿用前序变更的原路径。目前它仅存在于 `refactor-xlpa-entry-and-permissions` 与 `redesign-engineer-archive-template` 的 delta 中，尚未同步到 `openspec/specs/`；本变更不把它伪装成已归档主规范，也不创建同义能力。MODIFIED 条款以前两项变更依序形成的基线为准，未来同步／归档时按该顺序处理。

## Impact

- 实现影响：`mcp_server/archiving/` 的 generator、reader、models、engine、profiles；`edge_tools.py`、`edge_client.py`；`server.py` 的配置、工具登记、鉴权文件通道与能力展示；必要的文件传输辅助入口。
- 资源影响：`agent_assets/skills/xlpa/`、`xlpa-device-archiving/` 的技能说明、字段／端点参考与 manifest，以及 `mcp_server/tests/`。资源仍从 `agent_assets/skills` 分发，不修改 IDE 本地技能副本。
- 外部依赖：现有云端字典 API、边缘 `:7500` 建档后端、openpyxl 与现有 HTTP 客户端；不引入数据库、消息队列、对象存储或新的协议转换引擎。
- 本变更为独立后续规划，原变更文件与 20/25 任务进度保持原样；原未完成验收不自动转为通过。本变更全部实施任务重新跟踪，覆盖与新要求相关的回归。
- 非目标：新增其他设备类型、更新／迁移既有档案、全量覆盖式下发、校时或设备控制、修复23门户、修改后端协议、重做云端权限系统。本轮只生成规划，不修改代码或 Excel，不操作现场设备。
