# web-chat-ui Specification（delta）

## ADDED Requirements

### Requirement: 助手消息必须以富内容渲染呈现且渲染前必须消毒

助手消息文本 MUST 按 markdown 渲染为富内容呈现：标题、列表、表格、行内
代码与围栏代码块 MUST 渲染为对应的展示形态（表格为可读表格、代码为等宽
代码块）；围栏代码块 MUST 提供语言语法高亮与一键复制入口。```mermaid
代码块 MUST 渲染为图形（流程图/时序图/状态图）。全部由助手内容派生的
HTML MUST 先经白名单消毒后才可注入页面（默认拒绝未在白名单内的标签、
属性与事件处理器）；图形渲染 MUST 在禁用脚本执行与外部访问的严格安全
模式下运行。渲染或消毒失败 MUST 降级为纯文本/源码展示并给出可辨识提示，
MUST NOT 吞掉内容，MUST NOT 中断后续事件渲染。断线重连、刷新回放与
实时流三条路径的助手消息 MUST 呈现一致的富渲染形态。

#### Scenario: markdown 表格可读呈现

- **WHEN** 助手回复包含 markdown 表格语法（如协议点表）
- **THEN** 页面渲染为带表头与边界的表格，竖线与井号不以原始字符暴露

#### Scenario: 代码块高亮与复制

- **WHEN** 助手回复包含围栏代码块（如 JSON 配置样例）
- **THEN** 该代码块以等宽代码块呈现并按语言着色，提供复制入口且复制内容
  与源码一致

#### Scenario: mermaid 图形渲染

- **WHEN** 助手回复包含 ```mermaid 代码块
- **THEN** 页面渲染出对应图形（流程图/时序图/状态图），不显示原始语法文本

#### Scenario: mermaid 语法错误降级

- **WHEN** 助手输出的 mermaid 代码块无法解析为图形
- **THEN** 页面显示原始源码与错误提示条，内容不丢失，后续消息继续正常渲染

#### Scenario: 注入内容不执行

- **WHEN** 助手回复中携带被诱导注入的脚本或事件处理器（如
  `<script>`、`<img onerror>`，源于用户上传文档的转述）
- **THEN** 页面不执行任何脚本、不发起外部请求，内容按消毒后的安全形态或
  纯文本降级呈现

#### Scenario: 回放路径渲染一致

- **WHEN** 用户刷新页面或断线重连后回放历史助手消息
- **THEN** 历史消息与实时收到的消息呈现一致的富渲染形态（表格/代码块/图形）

### Requirement: 流式渲染必须节流且以最终精确渲染收尾

助手文本增量到达期间，前端 MUST 以固定节流间隔重渲染富内容（不逐字重渲染），
未闭合的 markdown 语法 MUST 按文本兜底展示，MUST NOT 产生报错或闪烁性
样式抖动。本轮文本块结束时 MUST 做一次最终精确渲染，修正流式期间的临时
呈现。用户向上翻阅历史内容时 MUST NOT 被强制拉回底部；贴底跟随滚动行为
MUST 保持既有体验。

#### Scenario: 流式期间表格逐步成型

- **WHEN** 助手正在输出一段 markdown 表格且尚未输出完毕
- **THEN** 页面在节流间隔内呈现已到达部分的表格形态，用户无需等待本轮结束
  才能看到表格

#### Scenario: 结束时最终渲染修正

- **WHEN** 一轮文本输出结束，流式期间存在未闭合语法（如半个代码围栏）
- **THEN** 页面最终呈现为正确的富内容形态，无残留的临时文本形态

#### Scenario: 上翻不被拉底

- **WHEN** 用户在助手输出期间向上滚动查看历史消息
- **THEN** 视口保持在用户所在位置，不被自动拉回底部；用户回到贴底后恢复
  跟随滚动

### Requirement: 用户消息必须保持纯文本呈现

用户输入的消息 MUST 按纯文本呈现，MUST NOT 被解释为 markdown（用户输入的
`#`、`*`、竖线等字符 MUST 原样显示）。

#### Scenario: 用户输入语法字符原样显示

- **WHEN** 用户输入含 `#`、`*`、`|` 等字符的普通文本
- **THEN** 消息气泡按原样显示这些字符，不出现标题、加粗或表格样式

### Requirement: 移动端宽表格必须可在气泡内横向滚动

助手消息表格 MUST NOT 撑破气泡或消息区布局；列数超过视口宽度时 MUST 可
在气泡内横向滚动触达全部列。表格横向滚动 MUST NOT 劫持或打断消息区的
纵向滚动与页面既有手势。

#### Scenario: 手机横滑查看多列表格

- **WHEN** 用户在手机浏览器查看含多列协议点表的助手回复
- **THEN** 表格在气泡内可横向滑动查看全部列，页面布局无横向溢出

#### Scenario: 横滑不打断纵向滚动

- **WHEN** 用户在表格上横向滑动后改为纵向滑动消息区
- **THEN** 消息区正常纵向滚动，无手势冲突或滚动卡死
