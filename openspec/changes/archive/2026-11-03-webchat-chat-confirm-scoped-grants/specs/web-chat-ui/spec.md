## MODIFIED Requirements

### Requirement: 写入确认卡片必须呈现参数摘要且未确认零写入

前端收到 `gate_blocked` 事件时 MUST 按"是否需用户补充参数"分流，而非一律弹卡：

- 当被拦工具在参数登记表（`GATED_PARAM_REGISTRY`）中登记了需用户直接提供、
  且模型常缺失的入参（如 `edge_get_token` 的边缘凭据）时，前端 MUST 弹出
  **参数表单卡**并暂停本轮进度，卡片按登记项渲染输入：敏感项以掩码输入、
  必填项标注、已由模型提供的必填项预填（敏感项不预填），使用户提交对象与
  模型将提交对象一致。
- 对**仅需确认、无需补参**的写入，前端 MUST NOT 弹出会暂停进度的模态确认卡；
  其确认 MUST 由**会话内**承载：门禁拒绝回传模型后，模型 MUST 在会话流播报
  将执行的操作名与**关键参数摘要**（品牌/型号/计划标识/影响台数等；一键建档类
  由后端按计划域数据反查，反查不足时明示"摘要不可用，仅显示计划标识"），并
  请求用户回复口令 `/确认`；收到口令即铸票并续跑。
- 绝对禁止类与护栏自纠错类拦截（`confirmable` 为 false，如业务登录、内置读
  越界）确认亦无法解除，MUST NOT 弹出会暂停进度的确认卡，MUST 降级为一行
  弱提示（不打断转圈、不进待确认队列）。

无论经卡片提交还是会话口令，用户确认前，系统 MUST 不发生任何平台写入
（后端门禁保证，前端不得预铸造票据）。确认动作 MUST 调用既有 confirm 端点
铸票，并 MUST 在事件流中可见确认结果；用户拒绝或不操作时写入 MUST NOT 发生。
当确认成功但本轮仍在执行（`turn_running`）时，前端 MUST NOT 丢弃续跑，而 MUST
把"带参续跑/发起新一轮"登记为待办，在本轮结束（`turn_done`）时自动补发。

确认所用端点 MUST 遵守后端写租约前置：当前连接未持有写租约时，前端 MUST
先获取租约再发起确认，MUST NOT 把租约冲突（409）当作业务失败提示用户；
租约过期时 MUST 能重新获取并重发确认。

#### Scenario: 确认卡片含参数摘要

- **WHEN** agent 请求一项需补参的写入（如 `edge_get_token`）而被门禁拦下
- **THEN** 参数表单卡展示操作名与关键参数摘要（模型已提供的非敏感项预填、
  敏感项掩码留空），用户确认前写入不执行；仅需确认的无参写入其等价摘要
  改在会话流播报后再请用户回复 `/确认`，确认对象与将提交对象始终一致

#### Scenario: 参数表单卡收集凭据

- **WHEN** agent 调用登记了入参的工具（如 `edge_get_token`）被门禁拦下
- **THEN** 弹出参数表单卡、暂停本轮进度，用户填写凭据并提交后写入才执行，
  事件流出现确认通过记录

#### Scenario: 无参写入经会话口令确认

- **WHEN** agent 请求一项无需补参的写入而被拦
- **THEN** 不弹出暂停进度的模态卡；模型在会话流播报操作与参数摘要并请求
  回复 `/确认`，用户回复后铸票、写入执行

#### Scenario: 未确认零写入

- **WHEN** 写入门禁拦下后用户既不提交表单也不回复 `/确认`
- **THEN** 对应写入未发生，后续同目标写入请求仍被门禁拦截

#### Scenario: 确认落在执行中轮次时续跑不丢失

- **WHEN** 用户在轮次仍在执行（`turn_running`）时完成确认
- **THEN** 续跑被登记为待办并在本轮 `turn_done` 自动补发，不出现"点了没反应、
  任务停住"

#### Scenario: 租约缺失时先取租约

- **WHEN** 用户确认而当前连接已不再持有写租约
- **THEN** 前端先重新获取租约再发起确认，最终确认成功，不向用户展示租约类
  错误文案

#### Scenario: 绝对禁止类拦截降级为弱提示不暂停进度

- **WHEN** 前端收到 `confirmable` 为 false 的 gate_blocked 事件（如业务登录、
  内置读越界）
- **THEN** 不弹出会暂停进度的确认卡，改呈现一行弱提示，本轮转圈与执行
  不被打断，事件流仍保留该拒绝记录
