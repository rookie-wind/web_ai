## Purpose

定义 webchat 浏览器前端单页应用的行为契约：登录准入、会话管理、消息
收发与事件流实时渲染、写入确认交互（含参数摘要）、ask_user 补充输入、
产物上传与下载入口。前端是既有 webchat API 的纯消费方，不新增后端
行为；凭据 MUST NOT 进入 URL。

## ADDED Requirements

### Requirement: 前端必须提供登录页并以会话凭据访问全部 API

webchat MUST 在自身端口提供一个不需要预置凭据即可打开的单页入口；未登录
时 MUST 仅呈现登录表单。登录 MUST 调用既有账号鉴权接口，成功后前端仅
持有返回的会话凭据（内存保存），此后全部 API 调用 MUST 以请求头携带该
凭据。登录失败 MUST 显示脱敏错误，MUST NOT 回显明文口令。

#### Scenario: 未登录访问

- **WHEN** 用户直接打开 webchat 地址且未登录
- **THEN** 页面只显示登录表单，不请求任何会话数据

#### Scenario: 登录成功跳转会话列表

- **WHEN** 用户输入正确账号密码登录
- **THEN** 页面进入会话列表，后续 API 请求头均携带会话凭据

### Requirement: 前端必须支持多会话管理与并行任务

前端 MUST 支持创建、列出、关闭与删除会话，同一用户 MUST 可并行持有
多个任务会话（受后端配额约束）。会话列表 MUST 区分活跃与已关闭状态；
创建会话被后端配额拒绝时 MUST 向用户展示明确原因。发送消息与确认类
操作 MUST 满足写租约前置（后端既有约束）：前端进入会话 MUST 先获取
写租约并在租约丢失时自动重取，MUST NOT 把租约类错误（403/409）
当作业务失败展示给用户；只读旁观可不持租约。

#### Scenario: 同用户多任务

- **WHEN** 用户在一个会话执行建档的同时新建另一个会话发起查询
- **THEN** 两个会话独立可用，互不干扰消息与事件流

#### Scenario: 租约丢失后自动恢复

- **WHEN** 用户发送消息时写租约已过期易手
- **THEN** 前端重新获取租约后重发，用户视角消息发送成功，无租约错误文案

### Requirement: 消息流必须实时渲染完整事件并支持断线回看

前端 MUST 经事件流通道实时渲染会话事件（文本增量、工具调用与结果、
产物、门禁拦截、ask_user），刷新或断线后 MUST 凭事件游标重放回看完整
过程。工具调用展示 MUST 可读（工具名与参数摘要），MUST NOT 展示任何
原始凭据。渲染 MUST 分层：进行中回合实时滚动，历史回合可折叠回看。

契约内未定义具体语义的未知类型事件（type=unknown）MUST 被安全忽略或
降级展示，MUST NOT 中断渲染流。本轮结束（收到 turn_done）时若本轮没有
任何可见文本，前端 MUST 回落展示本轮最终结果，MUST NOT 产生空白气泡。
作为“本轮结束”判据的轮次标识 MUST 取事件中的轮次序号字段，MUST NOT
以事件序号推算。

#### Scenario: 断线重连不丢事件

- **WHEN** 事件流连接中断后前端以最后游标重连
- **THEN** 中断期间产生的事件被补收，画面与完整过程一致

#### Scenario: 刷新后回看

- **WHEN** 用户刷新浏览器并重新进入同一会话
- **THEN** 页面回放该会话全部已持久化事件，包括此前的确认与拦截记录

#### Scenario: 未知事件不破坏渲染

- **WHEN** 事件流中出现前端未预期类型的事件
- **THEN** 页面仍正常渲染后续事件，无脚本异常中断，无凭据或原始结构直接展示

#### Scenario: 本轮无文本时不出现空白气泡

- **WHEN** 某轮结束但未产出任何文本增量事件
- **THEN** 页面展示本轮最终结果或明确的状态提示，不留下无内容的空气泡

### Requirement: 写入确认卡片必须呈现参数摘要且未确认零写入

当前端收到 gate_blocked 事件（写入门禁已拒绝一次调用，事件携带工具名与
参数摘要）时，前端 MUST 弹出确认卡片，卡片 MUST 展示将执行的操作名与
**关键参数摘要**（如品牌/型号/计划标识/影响台数），使用户确认的对象与
模型将提交的对象一致；一键建档类操作的摘要由后端按计划域数据反查
获得（非仅工具入参），反查不足时卡片明示"摘要不可用，仅显示计划
标识"。用户点击确认前，系统 MUST
不发生任何平台写入（后端门禁保证，前端不得预铸造票据）。确认动作
MUST 调用既有 confirm 端点铸票，并 MUST 在事件流中可见确认结果；
用户拒绝或不操作时写入 MUST NOT 发生。

确认所用端点 MUST 遵守后端写租约前置：当前连接未持有写租约时，前端
MUST 先获取租约再发起确认，MUST NOT 把租约冲突（409）当作业务失败
提示用户；租约过期时 MUST 能重新获取并重发确认。

#### Scenario: 确认卡片含参数摘要

- **WHEN** agent 请求执行建档写入
- **THEN** 卡片展示操作名与关键参数摘要，用户确认后写入才执行，
  事件流出现确认通过记录

#### Scenario: 未确认零写入

- **WHEN** 确认卡片出现后用户关闭页面未确认
- **THEN** 对应写入未发生，后续同目标写入请求被门禁拦截

#### Scenario: 租约缺失时先取租约

- **WHEN** 用户点击确认而当前连接已不再持有写租约
- **THEN** 前端先重新获取租约再调用确认，最终确认成功，不向用户展示
  租约类错误文案

### Requirement: ask_user 交互环必须可在页面完成补充输入

前端 MUST 支持两种提问来源并在会话界面呈现提问内容与补充输入入口：
事件型（事件流出现 ask_user 事件）与本轮结束型（本轮以模型提问文本
结束且未发起工具调用）。用户提交补充后 MUST 以普通消息进入同一会话
使流程继续并保持已有上下文。提问
内容 MUST 保留在历史回看中可见。

#### Scenario: 补充信息后续跑

- **WHEN** agent 因缺少必填字段发起 ask_user，用户在输入框补充后提交
- **THEN** 会话继续执行且不再重复同一提问

#### Scenario: 本轮以提问结束时同样可补充

- **WHEN** agent 未产生 ask_user 事件，而是本轮以一句待补充的提问结束
- **THEN** 页面仍呈现补充输入入口，用户补充后下一轮沿用同一会话上下文

### Requirement: 产物必须可在页面上传与下载且凭据不进 URL

前端 MUST 提供文件上传入口（表格/文档/图片，走既有上传通道），上传
成功 MUST 可将其引用随消息发送。事件流出现 artifact 事件时，前端 MUST
提供该产物的下载入口；下载 MUST 经请求头或一次性票据由后端代理取回，
URL MUST NOT 携带会话凭据或一次性票据原文。

#### Scenario: 上传驱动建档

- **WHEN** 用户上传已填建档表格并要求执行
- **THEN** 文件进入会话工作区，流程使用其内容

#### Scenario: 产物下载不暴露凭据

- **WHEN** 用户点击产物下载
- **THEN** 下载成功，浏览器地址与历史记录中不出现凭据

### Requirement: 前端必须可在移动浏览器正常使用

页面 MUST 采用响应式布局，主流移动浏览器 MUST 可完成登录、对话、
确认与下载全流程；确认卡片在移动端 MUST 完整展示参数摘要且按钮可
触达。

#### Scenario: 手机完成确认闭环

- **WHEN** 用户在手机浏览器收到写入确认卡片
- **THEN** 可阅读完整摘要并完成确认或拒绝
