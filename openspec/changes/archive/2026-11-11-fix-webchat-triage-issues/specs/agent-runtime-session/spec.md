## ADDED Requirements

### Requirement: 会话创建必须异步完成并具备状态机

会话创建 MUST 拆分为快路与慢路：快路（配额检查、凭据铸造、工作区创建、会话注册）
MUST 在 1 秒内完成并返回会话标识，MUST NOT 等待平台授权激活与模型清单；慢路
（平台授权激活、CLI 实例连接、账号模型清单拉取与预选模型设置）MUST 在后台执行，
其中平台授权激活与 CLI 连接/模型清单 MUST 并行推进。会话 MUST 具备
`creating → ready / failed` 状态：就绪时 MUST 向该会话事件流写入 `session_ready`
事件；失败时 MUST 写入 `session_failed` 事件并携带可辨识原因（MUST NOT 含凭据）。
慢路 MUST 有总超时上限（默认 60 秒，可配），超时按失败处理。非 `ready` 状态的
会话 MUST 拒绝写路径（发送消息、上传文件、切换模型）并返回 409「会话初始化中，
请稍候」；租约、事件流订阅、历史回看、中止与关闭 MUST 不受状态限制。会话列表
响应 MUST 携带会话状态（及失败原因）。

失败或超时的会话 MUST 自动回滚：撤销接入凭据、物理删除工作区、实例槽位与每用户
配额 MUST 恰好释放一次（MUST NOT 双重释放、MUST NOT 泄漏计数）；失败会话记录
MUST 保留供用户查看原因并删除。慢路执行期间会话被关闭或删除时，慢路 MUST 立即
中止且 MUST NOT 向已删除会话写入事件；删除/关闭操作 MUST 先取消慢路任务再回收
资源。空闲回收扫描 MUST 跳过 `creating` 状态会话。快路的配额拒绝语义（全局活跃
上限、每用户上限、槽位繁忙）MUST 保持与既有同步创建一致。

#### Scenario: 创建请求秒回

- **WHEN** 用户提交新建会话（默认账号或自带 PAT）
- **THEN** 请求在 1 秒内返回会话标识，平台激活与模型清单在后台继续

#### Scenario: 就绪事件到达

- **WHEN** 慢路完成激活、连接与模型清单拉取
- **THEN** 事件流出现 `session_ready`，此后发消息/上传/切模型正常执行

#### Scenario: 激活失败转 failed

- **WHEN** 平台授权激活失败（凭据问题或平台不可达）
- **THEN** 事件流出现 `session_failed`（含可辨识原因），该会话凭据撤销、工作区
  删除、槽位与每用户配额各释放一次，后续创建不受影响

#### Scenario: 初始化中写路径被拒

- **WHEN** 会话处于 `creating` 状态时请求发送消息、上传文件或切换模型
- **THEN** 返回 409「会话初始化中，请稍候」，不产生轮次或文件落盘

#### Scenario: 初始化中删除会话

- **WHEN** 会话处于 `creating` 状态时用户删除该会话
- **THEN** 慢路被取消，已删除会话不再收到任何事件，工作区删除，槽位与配额各
  释放一次

#### Scenario: 初始化超时

- **WHEN** 慢路超过总超时上限仍未就绪
- **THEN** 会话转 `failed` 并按失败回滚，原因可辨识

#### Scenario: 刷新后状态可见

- **WHEN** 用户在初始化完成前刷新页面并重新进入
- **THEN** 会话列表与主视图按服务端状态呈现初始化中/就绪/失败

#### Scenario: 回收不误杀初始化会话

- **WHEN** 一个 `creating` 会话创建后短暂空闲
- **THEN** 空闲回收扫描跳过它，慢路继续执行至就绪或失败

## MODIFIED Requirements

### Requirement: 会话接入凭据必须完成平台授权激活

webchat 为会话签发的接入凭据 MUST 在会话进入 `ready`（对用户可写）之前完成平台
登录绑定，使该凭据发起的云端工具调用不处于未登录态。激活 MUST 由后端使用账号已预设
的凭据自动完成，MUST NOT 要求用户在页面输入手机号或短信验证码。激活失败 MUST 使
会话进入 `failed` 状态并经 `session_failed` 事件向用户给出可辨识原因，MUST NOT
出现 `ready` 但任何云端操作都会被拒绝的会话。

Agent MUST NOT 调用 `login` 工具，MUST NOT 在对话中索要平台手机号或短信
验证码；`login` 门禁保持绝对禁止。系统提示与技能文档 MUST 与预激活事实
一致；若云端工具返回认证失效，Agent MUST 如实告知用户并由服务端重新激活，
MUST NOT 降级为 Agent 登录或向用户索取凭据。

#### Scenario: 新建会话可直接执行云端只读

- **WHEN** 会话就绪后用户首次要求查询云端数据
- **THEN** agent 的工具调用返回真实数据，事件流不出现「需先登录」类拒绝，
  agent 也不向用户索取手机号或验证码

#### Scenario: 激活不向用户索取凭据

- **WHEN** 用户以账号密码登录 webchat 并创建会话
- **THEN** 全流程不出现要求用户补充平台手机号或短信验证码的环节

#### Scenario: 激活失败不留下不可用会话

- **WHEN** 会话初始化过程中的平台授权激活失败
- **THEN** 该会话转 `failed` 并经 `session_failed` 展示明确原因，写路径被拒绝，
  不出现「会话已就绪但一查就报错」的状态

#### Scenario: Agent 不调用 login

- **WHEN** 用户请求云端只读数据
- **THEN** Agent 直接调用 `get_*` 工具，不调用 `login`，也不要求用户提供
  手机号或验证码；若遇认证失效则如实告知并由服务端重新激活

### Requirement: 会话必须绑定一个 Qoder 云账号且会话级固定

每个 Web 会话 MUST 在创建时绑定恰好一个 Qoder 云账号，来源为服务端默认账号或
用户自带 PAT；账号凭据 MUST 在客户端构建时绑定、运行期 MUST NOT 切换（更换账号
MUST 新建会话）。自带 PAT MUST 仅经环境变量注入子进程，MUST NOT 出现在进程命令行
或日志。初始化阶段 MUST 校验所用 PAT 能成功取得该账号的模型清单，校验失败 MUST
使会话进入 `failed` 并给出可辨识原因，MUST NOT 出现 `ready` 但模型不可用的会话。
默认账号不可用（无服务端 PAT 且无本机登录态）时，失败原因 MUST 提示用户需自带
PAT。该账号是独立于 MCP 接入凭据、门禁票据、会话票据的另一层凭据，MUST NOT 改变
写门禁与审计归属。"记住 PAT"的持久化 MUST 仅发生在该次初始化就绪之后，失败
MUST NOT 写入账号库。

#### Scenario: 默认账号建会话

- **WHEN** 用户新建会话选择默认账号且默认 PAT 有效
- **THEN** 会话就绪后绑定默认账号，可取得该账号模型清单

#### Scenario: 自带 PAT 建会话

- **WHEN** 用户新建会话填入有效自带 PAT
- **THEN** 会话就绪后绑定该 PAT（仅经环境变量注入），模型清单可用

#### Scenario: 自带 PAT 校验失败

- **WHEN** 用户填入无效或过期的自带 PAT
- **THEN** 会话转 `failed` 并给出可辨识原因，前端回填原因供修改重试，不产生
  可对话但模型不可用的会话

#### Scenario: 账号会话级固定

- **WHEN** 会话已绑定某 Qoder 云账号
- **THEN** 运行期不切换该账号凭据；更换账号须新建会话

#### Scenario: 默认账号不可用

- **WHEN** 既无服务端 PAT 也无本机登录态
- **THEN** 会话转 `failed`，失败原因提示需自带 PAT

### Requirement: 空闲会话必须自动回收

系统 MUST 跟踪会话最后活动时间；最后活动超过可配置空闲阈值（默认 1800 秒）
且当前无执行中轮次时，MUST 自动结束该会话。回收 MUST 采用 close 语义：撤销
会话凭据、释放实例槽位、写入 `session_closed` 事件（含 `reason=idle`），
MUST NOT 物理删除会话工作区与已登记产物（仍按保留期留存）。消息发送、租约
心跳、写入确认、SSE 连接存在、上传与下载均 MUST 刷新活动时间；执行中的轮次
与初始化中的会话（`creating`）MUST 跳过回收。

#### Scenario: 浏览器关闭后的会话被回收

- **WHEN** 用户关闭浏览器且超过空闲阈值未再操作该会话
- **THEN** 该会话被自动结束，槽位释放给其他用户；工作区产物仍按保留期留存

#### Scenario: 页面仍开着的会话不被回收

- **WHEN** 会话的 SSE 连接持续存在（页面未关闭）
- **THEN** 活动时间持续刷新，不触发空闲回收

#### Scenario: 执行中的轮次不被回收

- **WHEN** 会话正在执行 Agent 轮次且已超过空闲阈值
- **THEN** 本轮不被打断，轮次结束后再按空闲规则处理

#### Scenario: 初始化中的会话不被回收

- **WHEN** 会话处于 `creating` 状态且创建后暂无用户活动
- **THEN** 回收扫描跳过该会话，初始化继续执行
